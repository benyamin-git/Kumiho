# Kumiho v0.2.0 — Windows Release + Hygiene — Implementation Plan

**Status:** Draft
**Plan date:** 2026-10-10
**Spec:** [docs/superpowers/specs/2026-10-10-v0.2.0-windows-release-design.md](../specs/2026-10-10-v0.2.0-windows-release-design.md) (approved; commits 54f0054 + 5cb02dc)
**Starting point:** `main` @ 5cb02dc (clean; multiplatform core landed; CI green at 4c0137e)

## Global constraints (verbatim from the spec)

> zero Linux behavior change; Go 1.27.1; control protocol v1 byte-compatible;
> engine untouched; provider seam consumed as-is (additive-only if unavoidable);
> deps vendored; every task ends green (`make lint`, `make test`,
> `go test -race -count=1 ./...`, `make build`, Windows/Android cross-builds).

Additional frozen values: UA stays `MozillaVPN/2.35.0 (sys:linux; iap:true)`
(D25); MTU default 8500 (D20); pipe `\\.\pipe\kumiho\control` (D7/D19); service
name and local group `kumiho`; binary `%ProgramFiles%\Kumiho` + machine PATH
(D26); service LocalSystem, auto-start, recovery, autoconnect default ON
(D6/D23); WFP dynamic kill switch (D9); wintun.dll 0.14.1 committed under
`third_party/wintun/` (D11); `go-winio` v0.6.3 and
`golang.zx2c4.com/wintun v0.0.0-20230126152724-0fa3db229ce2` (vendored).

## Standard gate (every task, on top of any task-specific checks)

```
make lint && make test && go test -race -count=1 ./... && make build \
  && GOOS=windows GOARCH=amd64 go vet ./... && GOOS=windows GOARCH=amd64 go build ./... \
  && GOOS=android GOARCH=arm64 go build ./...
```

All commands exit 0. Windows-tagged tests execute in the `windows-latest` CI
job added in T2; before the next push, `go vet`/`go build` for windows plus the
local Linux suites are the local evidence (CI confirmation lands with the
first push, as in the previous cycle).

### T11 — `platform/windows`: WFP kill switch

**Files:** new `internal/platform/windows/wfp.go`, new
`internal/platform/windows/wfp_test.go` (`//go:build windows`),
`internal/platform/windows/netcfg.go`
**Interface:** `type wfpBlocker struct { ... }` with
`func openWFPBlocker() (*wfpBlocker, error)`,
`func (b *wfpBlocker) apply(permit []wfpPermit, blockAll bool) error`,
`func (b *wfpBlocker) clear() error`, `func (b *wfpBlocker) close()`.
`wfpPermit` is a small struct (interface LUID / app path / address set).
- Dynamic session (`FWPM_SESSION_FLAG_DYNAMIC`) on `fwpuclnt.dll`; provider +
  sublayer; filters in order: permit loopback; permit the service process
  (`FwpmGetAppIdFromFileName0` on the current exe); permit the tunnel interface
  (adapter LUID); permit DHCPv4/v6 and NDP; permit DNS (UDP/TCP 53) to the
  configured DNS address; permit LAN and `spec.ExcludeCIDRs` when
  `spec.AllowLAN`/list non-empty; then `blockAll` (WireGuard-style).
- `netConfig.Apply`: `KillSwitch == true` → clear then `apply`; `false` →
  `clear`. `Cleanup` always clears. Filter application is idempotent.
- Crash caveat: dynamic objects die with the process; service recovery (T17)
  and start-time cleanup re-apply. Document in code comment.
**Tests (windows job):** permit/filter spec builders; apply/clear on a
non-elevated context must return a clear error (skips when WFP engine open
fails in CI — reason printed).
**Verification:** standard gate; engine kill-switch toggle path untouched
(`ApplySetting` → `ReapplyNetcfg` → `netConfig.Apply`).
