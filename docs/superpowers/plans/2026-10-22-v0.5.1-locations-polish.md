## Global constraints (apply to every task)

### Behavior invariants

- **Flags:** trim, uppercase, then accept only exactly two ASCII letters;
  `REC`, blank and everything else returns no flag. The mapping is
  `U+1F1E6 + (letter - 'A')` per letter. No flag on city rows, server rows or
  `Recommended`.
- **Ping all target rule:** every country (including `REC`), every city, every
  server; skip `quarantined`; skip entries without a usable connect target;
  dedupe by lowercased `host:port`, keeping the first spelling. It ignores the
  filter, the query and the expansion state.
- **Test speed:** unchanged visible-row behavior; the GUI keeps its 16-host
  cap. Nothing pings on load, typing, expanding, refreshing, resuming or
  toggling.
- **One ping run at a time:** Test speed and Ping all share one busy state.
  Starting either while either runs is ignored.
- **Ping windows:** `max(base, ceil(N / 24) × 1.5 s + 1.5 s)`. The GUI base is
  3 s; Android's injected base is 12 s in production; the TUI has no timer and
  ends when the pending set empties.
- **Expand/Collapse:** if any stored country or city is expanded, the label is
  `Collapse all` and the action clears both sets; otherwise the label is
  `Expand all` and the action adds every country code and every
  `country/city` key. It does not touch the selection, the TUI cursor, the
  filter or the persisted selection. It is disabled/no-op while the filter is
  non-empty (raw on GUI/Android, trimmed in the TUI), and disabled with no
  loaded tree.
- **No cancel:** no new IPC command, no progress streaming, no new protocol
  field, no settings key, no persistence.

### Copy and accessibility

- Flags are data, not accents. They do not change the palette, buttons, tone
  or status colours.
- Custom surfaces hide the flag from assistive tech: the GUI tree uses a
  separate `aria-hidden="true"` span; Android uses a separate prefix `Text`
  wrapped in `clearAndSetSemantics {}` (and a `clearAndSetSemantics` plain
  content description for the one-line selection summary). The native GUI
  `<select>` includes the flag in its option text; that is the one accepted
  exception (D5).
- All new copy is English and lives in the existing string resources/CSS
  conventions. No new font, image or network asset ships with the app; Noto
  Color Emoji is a screenshot-host prerequisite only (Task 8).

## Pre-flight clarifications (resolved here, none open)

These are implementation details needed to make the approved decisions
coherent. They do not change the product scope or the success criteria.

- **C1 — a failed Ping all retries Ping all.** A failed Ping all gets its own
  notice action and copy (`Ping all could not start.`), and its one **Retry**
  repeats Ping all, not Test speed. Test speed keeps its existing retry. This
  does not add a new retry control; it keeps the one-retry rule honest.
- **C2 — the GUI flag is a sibling span, never part of the label text.** The
  country tree row keeps a plain country label and gets a decorative
  `aria-hidden` flag span. This is the only way to satisfy D5 without making
  screen readers announce the flag.
- **C3 — Android flag decoration is a prefix text, not a changed title.** The
  `KumihoRow` title stays the plain country name; a separate prefix `Text`
  with `clearAndSetSemantics {}` draws the flag. The subtitle (including the
  connect sheet's `Saved selection` row) is unchanged. The selection summary
  is a single `Text` whose visual string includes the flag but whose semantics
  are the plain `Country · City · host` line.
- **C4 — the Android helper counts targets, not rows.** `X visible · Y total`
  means `state.testTargets.size` and `state.allTargets.size`: the deduped,
  non-quarantined Test-speed set and the deduped, non-quarantined whole-tree
  set. This keeps the helper truthful next to both buttons.
- **C5 — the TUI tracks both `p` and `P`.** A single `*pingRun` gives TUI
  Test speed and Ping all the same mutual exclusion. Only a Ping-all run shows
  the `pinging N servers...` line. `pingHosts` reports a command failure so the
  run state clears and the existing notice row explains it; successful runs
  still end from the streamed results.
- **C6 — filtering predicates match the spec verbatim.** GUI uses
  `view.filter !== ""`; Android uses `query.isNotEmpty()`; the TUI uses
  `strings.TrimSpace(filter) != ""`. The existing "searching" predicates
  (trimmed/blank-based) still control filter-forced expansion and no-match; the
  toggle predicate is the one above.
- **C7 — Ping all is disabled where it cannot run.** GUI and Android disable
  the button when the all-target set is empty; the TUI `P` is a no-op. This
  mirrors the existing empty-tree states and avoids a command that would do
  nothing.
- **C8 — the Android 512-host facade cap is unchanged.** A list larger than
  512 would be refused by the existing facade and surface the existing failure
  notice; today's list is 35. No truncation or new limit is added in the app.
- **C9 — the TUI footer grows to two help lines.** The pinging line sits above
  them; the help overlay gets a second locations line. This keeps the 100-column
  capture readable without dropping an existing key hint.
- **C10 — no JS unit-test harness is added.** The shared flag module gets
  syntax checks, and the existing Playwright visual harness exercises the real
  page; the Go tests continue to cover the embedding. Adding a JS test runner
  is out of scope.

when it is empty. A result for an unrequested host still updates `rtts` but
does not touch the run.

  return; call `m.startPing(true, hosts)`.
- `x`: if `strings.TrimSpace(m.loc.filter) != ""`, return; call

still edits the filter.

 * The ISO 3166-1 alpha-2 flag emoji for a country code, or "" for REC,
 * blank, or anything that is not exactly two ASCII letters after trimming.

export function flagFor(code) {
  const normalized = String(code == null ? "" : code).trim().toUpperCase();
  if (normalized === "REC" || !/^[A-Z]{2}$/.test(normalized)) return "";
  return String.fromCodePoint(
    0x1F1E6 + normalized.charCodeAt(0) - 65,
    0x1F1E6 + normalized.charCodeAt(1) - 65,

}

**Flag helper**

```kotlin
object CountryFlags {
    /** The ISO 3166-1 alpha-2 flag emoji, or "" for REC, blank or a non-ASCII code. */
    fun emoji(code: String?): String {
        val normalized = code.orEmpty().trim().uppercase(Locale.ROOT)
        if (normalized == "REC") return ""
        if (normalized.length != 2 || normalized.any { it !in 'A'..'Z' }) return ""
        val base = 0x1F1E6
        return String(Character.toChars(base + (normalized[0] - 'A'))) +
            String(Character.toChars(base + (normalized[1] - 'A')))
    }
}
```

Use `Locale.ROOT`; do not rely on the device locale for uppercasing. Keep the
helper in the `ui.locations` package so the picker, the screen and the
selection summary share one mapping. `"REC"` after `Locale.ROOT` uppercasing is
the same value as `LocationTree.RECOMMENDED_CODE`; the literal keeps this
helper independent of the tree object.

## Risks and mitigations

- **Windows flag fallback.** Windows 11 shows regional-indicator letters.
  Accepted by D2; the country name and code remain present, and the fallback
  is documented in AGENTS/CHANGELOG.
- **Emoji font dependency.** The Linux captures will show fallback letters
  without Noto Color Emoji. The harness fails early with an actionable install
  command; the plan installs the font before capturing.
- **TUI width.** The flags are wide and the footer grew by one line. The
  capture is the visual check; the two footer lines are under 100 columns and
  the sample tree still fits 28 rows.
- **No JS unit tests.** The shared helper is small and syntax-checked; the real
  page is exercised by the Playwright capture. The Android and Go mappings are
  unit-tested, so a three-language drift would be caught on two sides.
- **Android connected suite.** It is slow and needs the AVD. It is a stop/go
  gate because the new Compose controls and semantics live there. Do not claim
  completion without it.
- **512-host facade cap.** The app keeps the existing cap; a future list above
  512 would surface the existing failure notice. Today's list is 35.
- **Long Ping all runs.** The dynamic window and the disabled buttons keep the
  UI honest, but there is no cancel (D10). A future cancellation needs new
  protocol surface; it is out of scope.
- **Rollback.** Every change is client-local and additive. Revert the task
  commits in reverse order; there is no migration, protocol change or
  persisted state to clean up.
