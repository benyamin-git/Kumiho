**Status:** Approved (gate #2, 2026-10-31)
**Date:** 2026-10-31

**Design spec:**
[2026-10-31-v0.9.0-region-truth-design.md](../specs/2026-10-31-v0.9.0-region-truth-design.md)
(approved 2026-10-31, commit `f09e134`).

**Goal:** implement the approved spec as a sequence of small, reviewable,
green commits, then ship it as the full `v0.9.0` release: all five remaining
v0.8.0 region/location-truth items, the A2 browser fix, the new surfaces on
every client, the CLI live sign-in proof before the tag, and the post-release
phone WebView check.

Naming note: the **A2 browser fix** is the already-committed `ce9d501 fix:
omit the redirect URI from browser sign-in`. The plan-local task **A2** below
is “relay settings and secret storage”; the two A2 labels are unrelated.

This plan uses the spec's decisions as fixed. It does not re-open them. A few
implementation-level choices are called out as **derived** where the spec
delegates the exact mechanism; they are within the approved decisions and are
listed here so the gate can catch any mismatch.

## Global constraints

- Go 1.27.1, vendored dependencies, no new third-party Go modules (D39). The
  Worker template is plain JavaScript.
- Protocol v1 stays byte-compatible. New IPC commands/events and new payload
  fields are additive; existing envelopes and fields do not change (D40).
- State changes are additive; older clients ignore new fields; downgrading
  leaves `favorites`, `recents` and `relay.token` in place (D40).
- One logical change per commit. Subject: `type: lowercase imperative summary`;
  types in use: `feat`, `fix`, `refactor`, `test`, `docs`, `ci`, `chore`.
- Every Go commit must at least pass `make lint` and `go test ./...`; the full
  gate before the tag is:
  `make lint && make test && go test -race -count=1 ./... && make build &&`
  `GOOS=windows GOARCH=amd64 go vet ./... &&`
  `GOOS=windows GOARCH=amd64 go build ./... &&`
  `GOOS=android GOARCH=arm64 go build ./...`.
- Android changes cannot run Gradle from this T3 thread. The `android` and
  `android-tv` CI jobs on the pushed commit are the Android evidence. The user
  may run `make android-test` outside T3; the plan does not depend on it.
- No live HTTP 451 environment. Mocks and fixtures are the acceptance (spec
  non-goals and D36).
- The browser sign-in page is not relayed; no live Fastly bypass is attempted.
- Never restart `kumiho.service`, the Android emulator, or a Gradle build from
  this T3 thread (AGENTS.md).
- Do not push until the release stage is reached. Push `main`, wait for CI,
  run the CLI proof, then tag. Never force-push, amend a published commit, or
  delete a published tag. The user explicitly requested the v0.9.0 push, tag
  and release watch (D2); the release stage is the only push in this plan.
- Release secrets must be verified before the tag; stop if any of the five
  `ANDROID_*` secrets are missing (D37).
- The phone WebView check is post-release; a failure becomes v0.9.1 (D32/D38).
- Android phone/TV screenshots are deferred to a post-release docs commit
  (D35); GUI/TUI screenshots are regenerated before the tag.
- `.ai-state` is scratch and stays out of commits.

## Derived implementation choices (within the approved decisions)

These are the only plan-level choices not spelled out by the spec. Review them
at gate #2; each is small to change before implementation.

1. **CLI settings and relay test.** The spec says the CLI prompts for the
   relay token and every client exposes Test relay. The plan adds
   `kumiho settings get|set|reset` and `kumiho relay test` rather than hiding
   the settings behind the TUI. The token is read with the existing
   `tty.ReadPassword` (no new dependency).
2. **CLI `--json` shape.** To include `favorites`, `recents`, `latency` and
   `allow_locked`, `kumiho locations --json` emits the full `LocationsResult`
   object instead of the current bare countries array. This is a CLI JSON
   change; the changelog will name it.
3. **GUI ping completion.** The GUI bridge carries state envelopes, not event
   envelopes. The controller projects `ping_done` as a monotonic
   `ping_done_seq` (plus `ping_busy`) in `gui.State`; the Locations JS ends the
   run when the sequence changes. The Android/TUI/CLI consume the real IPC
   event.
4. **TUI keys.** `f` toggles the star (D28); `c` clears recents from the Recent
   header (D25); `L` toggles `allow_locked` from the Locations footer (D18).
   These are the existing flat-locations key style.
5. **API ref types.** `settings.LocationRef` is the persisted form;
   `api.LocationRef` is the wire form. The engine maps between them so the
   settings package does not import the API package.
6. **CLI live proof’s interactive step.** The harness shell is non-interactive.
   The assistant builds and starts the dev daemon and runs the verification
   commands; the user runs the interactive `login` command in their terminal
   and completes the Firefox page. The redirect URL stays in the user's
   terminal, never in chat. The proof is still a real CLI browser sign-in.
7. **Relay test target.** The test is a direct relay request to the server-list
   head (`limit=1`), not a synthetic endpoint, per D11. It proves the Worker,
   token, allowlist and upstream in one call.
8. **`PingDone.Error`.** The preflight failures (not signed in, pass/quota,
   no visible targets) need a run-level error after the command has already
   been acknowledged. `PingDone` carries an additive `error` string; per-host
   failures remain nil RTTs.
9. **`LocationsResult.AllowLocked`.** The locations footer must say “Show
   locked locations” or “Hide locked locations” without a second
   `settings_get` round trip. The reply carries the additive `allow_locked`
   bool; the setting itself stays in `SettingsView`/`settings_set`.
10. **CLI presentation.** The default `kumiho locations` output keeps the
    country summary and adds a leading `*`/`~` marker (favorite wins when both
    apply). `--favorites` and `--recent` print resolved country/city/server
    rows instead; both flags together print the union, favorites first.
    `--ping --json` refetches locations after `ping_done` and emits the
    refreshed object.
11. **Android location result.** Keep `EngineClient.locations()` returning
    `List<Country>` for the Dashboard and add
    `locationsResult(refresh): LocationsResult` for the Locations screen. This
    avoids a mechanical change to the dashboard’s location picker.
12. **TUI clear action.** TUI section headings are not focusable, so `c`
    clears recents from anywhere on the Locations screen when the list is
    non-empty; the footer shows the action. This is the TUI form of the GUI’s
    Recent-header Clear button.
13. **GUI allow-locked refresh.** After a successful `settings_set` of
    `allow_locked`, the controller reloads locations (force, no network
    refresh) so the footer and rows update from the daemon’s filtered view;
    the settings JS needs no extra action.
14. **Release CI checks.** CI waits use single `gh run list`/`gh run view`
    checks, never `sleep`, loops or `gh --watch` (harness rule). If a run is
    still in progress, the turn ends with the run URL; it is resumed on the
    next turn before the CLI proof or tag.
15. **Relay Test signature.** `relay.Test(ctx, client, cfg)` takes the config
    explicitly instead of the spec’s shorthand `Test(ctx, http.Client)`. The
    daemon must build the relay URL even when no transport is wrapping a 451,
    and passing the config avoids reaching into the transport. The observed
    behavior (D11) is unchanged.
16. **Unresolvable refs.** D24’s “drop” is applied to the resolved view, not
    destructively to `state.json`: an unresolvable favorite/recent is omitted
    from `LocationsResult` but kept in state, so a location Mozilla restores
    later comes back. Toggling it off removes it permanently.

## Phase A — Control-plane relay and 451

### A1. The relay transport

**Commit:** `feat: add the control-plane relay transport`

**Files**

- `internal/relay/relay.go` (new)
- `internal/relay/relay_test.go` (new)

**Interfaces**

```go
package relay

type Config struct {
    URL   string // normalized HTTPS origin, e.g. https://relay.example
    Token string // optional; sent as X-Kumiho-Relay-Token
}

// ValidateURL accepts only an HTTPS origin: no userinfo, path, query or
// fragment. A trailing slash is normalized away. Empty is valid and means
// "no relay configured".
func ValidateURL(raw string) (string, error)

type BlockedError struct {
    Status          int    // the terminal upstream status (451)
    RelayConfigured bool
    RelayTried      bool
    RelayErr        error  // non-nil when the relay attempt failed
}

func (e *BlockedError) Error() string
func (e *BlockedError) Unwrap() error

// NewTransport wraps base. cfg is read on every request so a settings change
// applies without rebuilding clients. logf may be nil.
func NewTransport(base http.RoundTripper, cfg func() Config, logf func(string, ...any)) *Transport

func (t *Transport) RoundTrip(req *http.Request) (*http.Response, error)

// Test performs one direct request through the relay to the server-list head.
// It does not require an HTTP 451 and never follows redirects.
func Test(ctx context.Context, client *http.Client, cfg Config) (Result, error)

type Result struct {
    Status  int
    Latency time.Duration
}
```

**Behavior**

- Forward every request to `base` unchanged when the relay is not configured.
- On a `451` and a configured relay, discard and close the first response
  body (bounded drain), clone the request, replay the body (`GetBody`; if the
  body cannot be replayed, return the original 451 without retrying), rewrite
  the URL to `<relay>/<target-host><target-path><target-query>`, set the relay
  token header, and retry exactly once.
- Never retry a request whose target host is the relay host; this is the loop
  guard for the relay Test and any direct relay call.
- Enforce the D9 allowlist (`api.accounts.firefox.com`,
  `oauth.accounts.firefox.com`, `profile.accounts.firefox.com`,
  `vpn.mozilla.org`, `firefox.settings.services.mozilla.com`) before
  rewriting. A non-allowlisted 451 returns the original response, not a relay
  request.
- If the relay attempt also returns `451`, or the relay request fails, return
  `*BlockedError` with the exact fields above. Close the relay body.
- Preserve method, headers (except the token header added), body and query.
  Do not forward the relay token upstream. Do not log the token, the full
  target query, or the authorization header. Log only the target host and the
  relay outcome.
- `Test` builds the relay URL for the server-list head with
  `?limit=1`, sends `X-Kumiho-Relay-Token` when set, disables redirects with
  `CheckRedirect: func(...) error { return http.ErrUseLastResponse }` (or an
  equivalent per-call client), and measures wall time. A non-2xx result is a
  `Result` plus an error, not a panic.

**Tests (`relay_test.go`)**

- 200 pass-through: base called once, body/headers unchanged, no relay call.
- 451 + relay 200: one base call, one relay call; URL path/query/token exact;
  body replay; method and headers preserved; first body closed.
- 451 + relay 451: one retry only; `BlockedError{RelayConfigured:true,
  RelayTried:true, Status:451}`.
- 451 + no relay: `BlockedError{RelayConfigured:false}`; no relay call.
- 451 + relay transport error: `BlockedError` with `RelayErr`; one attempt.
- 451 + non-allowlisted host: no relay call; original response.
- 451 + non-replayable body: no relay call; original response.
- Request already addressed to the relay host: no retry loop.
- Token omitted when empty; set when present.
- `ValidateURL`: empty, https origin, trailing slash; reject http, userinfo,
  path, query, fragment, empty host, bad port.
- `Test`: success status/latency; token; 451/500 error; no redirect follow.

**Verification**

- `go test ./internal/relay`
- `go vet ./internal/relay`
- `make lint` (gofmt over the tree)

```go
type HTTPError struct{ Status int }
```

    docs/relay.md, then retry.”
  - relay failed: “Mozilla returned HTTP 451 and the configured relay failed:
    <reason>. Check the relay URL and token in Settings → Region.”
  - edge: “The VPN edge refused this region (HTTP 451). A control-plane relay

    the `RemoteError` instead of the raw error.
  - `Locations`: a 451 returns `region_blocked` immediately, without the

    copy where they return an error/string.
- `daemon` `TypeLocations` uses `replyCtrlErr` so `region_blocked` reaches the

- No retry beyond the relay's one attempt; no cache fallback for 451.

- Engine `Locations` 451 does not serve a cached list; a non-451 error still

- `Connect` 451 sets idle and returns `region_blocked`; no edge dial occurs

### A4. Edge 451 is terminal

**Commit:** `feat: treat an edge 451 as terminal`

**Files**

- `internal/engine/connect.go`
- `internal/engine/watchdog.go`
- `internal/engine/connect_test.go`
- `internal/engine/watchdog_test.go`

**Behavior**

- Add `isEdgeBlocked(err) bool` using `errors.As` to
  `*upstream.ConnectRejected` with `Status == 451`.
- In the initial `Connect` dial loop: a 451 breaks immediately, is not counted
  as a server failure, and is not retried through the alternate edges. Return
  `api.RemoteError{Code: api.CodeRegionBlocked, Message: edgeBlockedMessage}`.
  The state returns to idle via `connectFailed` (not FATAL; the user can fix
  their region and retry).
- In `redialOnce`/watchdog: a 451 returns `&fatalError{edgeBlockedMessage}` so
  the watchdog parks the state in FATAL with the message. It must not burn
  redial attempts or rotate edges.
- The control-plane relay does not affect this path (no relay call).
- The error text says a control-plane relay cannot fix the VPN data path.

**Tests**

- Fake `dialUpstream` returning `*upstream.ConnectRejected{Status:451}`:
  one dial, no alternate attempts, `region_blocked`, state idle.
- Watchdog redial 451: `fatalStop` called, no further dials, state FATAL.
- A 502/503 still uses the existing retry/backoff behavior.
- The 451 is not recorded in `failures`/quarantine.

**Verification**

- `go test ./internal/engine -run 'Connect|Watchdog|Edge'`
- `make lint && go test ./...`

### A6. Worker template

**Commit:** `feat: add the control-plane relay worker template`

**Files**

- `contrib/relay-worker/wrangler.toml` (new)

**Behavior**

```go
type PingDone struct {
    Total    int    `json:"total"`
    Answered int    `json:"answered"`
    Error    string `json:"error,omitempty"`
}

// engine
// PingHosts measures the visible candidates named by hosts. emit is called
// for every resolved host as it completes; the returned PingDone always
// carries the run totals, and Error for a run-level preflight failure.
func (c *Controller) PingHosts(ctx context.Context, hosts []string, emit func(api.PingResult)) api.PingDone
```

**Engine implementation**

- Constants: `pingProbeConcurrency = 4`, `pingProbeTimeout = 10 * time.Second`,
  `pingCacheTTL = 30 * time.Minute`; expose them as Controller fields
  (`pingConcurrency`, `pingTimeout`, `pingCacheTTL`) so tests use milliseconds.
- `PingHosts`:
  1. `countries, err := c.Locations(ctx, false)`; on error return
     `PingDone{Error: err.Error()}` (no events).
  2. Build a map of every visible `serverlist.Candidate` by canonical
     `Address()` (lower-cased key). Deduplicate requested hosts, preserve the
     request order, and resolve each to a candidate. Unknown hosts are
     skipped; if none resolve, return
     `PingDone{Error: "no visible locations to ping"}`.
  3. Ensure a pass: reuse `c.pass` when it has no expiry (`ExpiresAt == 0`)
     or expires more than 30 s from now; otherwise call `acquirePass`.
     Signed out returns `PingDone{Error: "Ping all needs a signed-in
     account"}`; quota/activation errors return the existing fatal text.
  4. Run the candidates through a four-worker pool. For each:
     - `probeCtx` with `pingTimeout`;
     - `upstreamOptions(probeCtx, cand, c.passFor(pass))`, then
       `dialUpstream` → throwaway `upstreamSession`;
     - `start := time.Now(); stream, err := sess.OpenStream(probeCtx,
       "vpn.mozilla.org", 443)`; the RTT is the wall time of this call only
       (dial time excluded, per D19);
     - close the stream and the session immediately, including on error;
     - record `{RTT, OK, MeasuredAt}` in the in-memory cache and emit
       `api.PingResult{Host: candidate.Address(), RTTMS: ptr-or-nil}`.
  5. Return `PingDone{Total: len(candidates), Answered: <finite results>}`.
- `PingHosts` never assigns `c.session`, never touches the SOCKS listener,
  metrics, routes or kill switch, and never cancels an active session. A
  connected tunnel keeps running during a run.
- Cache:
  - `pingMu sync.Mutex`, `pings map[string]pingSample` keyed by the
    lower-cased canonical address; `pingSample{RTT time.Duration, OK bool,
    MeasuredAt time.Time}`.
  - `prunePings(countries)` drops entries older than `pingCacheTTL` or not
    in the current visible candidate set; called on every read and at the
    start of each run.
  - C3 exposes the fresh entries on the wire; C1 only keeps the cache and a
    `CachedLatency(countries) map[string]pingSample`-style accessor.
- Pass plumbing fix: change
  `upstreamOptions(ctx, cand, pass *guardian.Pass)` to
  `upstreamOptions(ctx, cand, passFn func() string)`. Add
  `Controller.passFor(initial *guardian.Pass) func() string`: use the live
  `c.pass` when non-nil, else `initial`, else `""`. Connect and watchdog call
  `c.passFor(pass)`; ping calls the same with the acquired pass. This fixes
  the current ignored argument and the empty initial CONNECT token, while
  keeping pass-renewal visible to long-lived sessions (the closure reads the
  live `c.pass` first).
- `upstreamOptions` tests pass `nil` and keep their current behavior.

**Tests**

- Fake `dialUpstream`/`upstreamSession` (reuse the existing connect test
  fakes) records each temporary session, its `OpenStream` target
  (`vpn.mozilla.org:443`), and close calls.
- Per-candidate RTT and nil-failure results; totals/answered; unknown and

- Concurrency: at most 4 dials in flight; the fifth waits.
- Timeout: a stream that blocks past `pingTimeout` yields a nil RTT and the

## Risks and rollback

| Risk | Mitigation / rollback |
| --- | --- |
| No live 451 environment proves the relay end-to-end. | Mock coverage is the acceptance (D36). The Worker README and Relay Test give the user a real check after deploy. Do not claim a live 451 proof. |
| Edge 451 is terminal and the relay cannot fix it. | Distinct copy, settings hint, no retry burn; users retry after fixing region. The edge behavior is independent of the relay. |
| A new Mozilla JEXL expression hides the list. | Fail open on unknown/missing values with a debug warning; fixtures pin the live expressions; `allow_locked` reveals hidden rows. |
| A real ping run is slow or costly (temporary edges, quota). | 4 concurrent, 10 s per probe, 30 min cache, no auto-ping, one run per client, reuse the live pass. The UI shows progress until `ping_done`. |
| Ping failures look like unreachable locations. | Nil RTT is cached and labeled `timeout`/unreachable; preflight errors are run-level `ping_done.error`, not per-row. |
| Favorites/recents go stale as Mozilla rotates servers. | Exact server then first usable city server; unresolved refs are omitted from the view but kept for recovery; clear/toggle paths by resolved address. |
| IPC/state compatibility breaks older clients. | Additive fields/commands only; protocol v1 envelope unchanged; fixtures decode old payloads; state JSON omitempty. |
| The Android app and desktop diverge. | The engine owns filtering/ping/favorites; the facade and daemon expose the same results; Android CI is mandatory. |
| A2 sign-in fix is incomplete in the live flow. | The CLI proof gates the tag; a failure is fixed before tagging. The phone WebView check is post-release and becomes v0.9.1 if needed. |
| Android release secrets are missing/invalid. | Phase 0 and F2 check all five `ANDROID_*` secrets before the tag; stop if missing. |
| Screenshot harness drift or a leaked notice. | The script restarts the harness per screen; review all six images; re-run before committing. Android captures are deferred. |
| Push/tag/release is irreversible. | User approved the release (D2); no force-push/amend/tag moves; tag only the CI-verified SHA; verify the release before F4. |
| CI or the release run outlasts a turn. | Single non-blocking checks; hand back the run URL; resume next turn (derived choice 14). Never sleep/loop/`gh --watch`. |
