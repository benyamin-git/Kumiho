## Global constraints (verbatim from spec + repo rules)

- Go 1.27.1 (`go.mod`); targets linux/amd64, linux/arm64, windows/amd64 and
  android/arm64; no cgo; dependencies vendored — **no new dependency and no
  `vendor/` change**.
- Every commit leaves the gate green:
  `make lint && make test && go test -race -count=1 ./... && make build && GOOS=windows GOARCH=amd64 go vet ./... && GOOS=windows GOARCH=amd64 go build ./... && GOOS=android GOARCH=arm64 go build ./...`
- IPC control protocol v1: no envelope, command or existing-field change. The
  five new `SettingsView` fields are additive and optional; old clients ignore
  them.
- No `internal/platform` seam change; all wiring is engine-level.
- Stdlib only. No `utls`; fragmentation wraps `net.Conn`.
- Version comes from `git describe`/ldflags — v0.4.0 is docs/CHANGELOG only.
- Commit style `type: lowercase imperative summary`; never push or tag;
  `.superpowers/` and `.ai-state` stay out of commits.
- Tasks are commit-sized and may be paused after their commit. `[user]` marks a
  check that needs the Windows VM or a live network.

### M2 — B: TLS fragmentation

**T2.1 `feat: add the tls clienthello splitter`**
Files: `internal/tlsplit/tlsplit.go`, `internal/tlsplit/tlsplit_test.go`.
Interfaces: `type Mode int` (`Off`, `FirstByte`, `SNI`);
`func ParseMode(string) (Mode, error)`; `func Wrap(conn net.Conn, mode Mode) net.Conn`.
`Wrap` returns a conn that inspects only the first Write: a buffer that does not
start with `0x16 0x03 … 0x01` passes through unchanged; `first-byte` writes
`[0,1)` then `[1,end)`; `sni` parses the ClientHello (session id, cipher
suites, compression, extensions, server_name) and writes `[0,start)`,
`[start,start+1)`, `[start+1,end)`; other methods delegate. Malformed hellos
fall back to one write. This is best-effort, as upstream.
Verification: `go test ./internal/tlsplit/` — capture a real ClientHello
(`tls.Client` over `net.Pipe`), assert segment lengths and the SNI byte, complete
a handshake against a local TLS server in every mode, non-TLS and malformed
first writes pass through.

**T2.2 `feat: wire tls fragmentation into the engine`**
Files: `internal/upstream/session.go`, `internal/upstream/session_test.go`,
`internal/engine/connect.go`, `internal/engine/engine.go`,
`internal/engine/controller_test.go`.
Behavior: `upstream.Options` gains `WrapConn func(net.Conn) net.Conn`, applied
after the TCP/proxy connection and before `tls.Client`; `upstreamOptions` sets
it from `tlsplit.ParseMode(cfg.TLSSplit)` at connect time. `UseBypassDialer`'s
`newClient` wraps the control-plane `DialContext` result, reading the mode
inside the dial function, so FxA/Guardian/Remote Settings/solver pick it up on
their next request. DoH and bootstrap dials are not wrapped.
Verification: `go test ./internal/tlsplit/ ./internal/upstream/ ./internal/engine/`
— wrapper applied once, edge options carry the mode, control-plane handshake to
a TLS test server succeeds with `first-byte`, and DoH dials are untouched.

### M3 — C: Fastly challenge solver

**T3.1 `feat: add the fastly challenge solver`**
Files: `internal/fastly/fastly.go`, `internal/fastly/fastly_test.go`, `NOTICE`.
Interfaces: `type Solver struct { HTTP *http.Client; SharedJar http.CookieJar;
UserAgent string; Enabled func() bool; Logf …; Now func() time.Time; Rand *rand.Rand }`
and `func (s *Solver) Solve(ctx context.Context, challengedURL string) error`.
Behavior: port the FoxyVPN v1.0.7 algorithm (MIT): derive the origin; GET the
origin `/`; detect `/_fs-ch-` + `Client Challenge`; if absent, retry the related
apex (`api.` or `www.` label dropped), then fail. Fetch
`<prefix>/script.js?reload=true`; take the last
`init([…], "token", "prefix")`; answer `pow` (SHA-256 over `base` + a 2-char
alphanumeric suffix, target 32 bytes), `pat`
(`POST <prefix>/pat?token=…`, `Origin`, empty body; 400/401 → empty auth) and
`clientmetrics` (static non-bot JSON); POST `{token,data}` to
`<prefix>/fst-post-back`; on `status=success` re-fetch `/` to confirm, then copy
the isolated jar's cookies into `SharedJar` for the origin, apex and challenged
URL; otherwise take `ch`/`tok` for up to three rounds. Budget 60 s, 250–750 ms
jitter between rounds, warn log per attempt, unsupported/captcha and
`ErrDisabled` (when `Enabled` is false) are specific errors. No browser
automation.
Verification: `go test ./internal/fastly/` — fixture server (pow then success;
pat/clientmetrics), apex fallback, cookie installation, captcha error,
disabled, caps/jitter with injected clock/rand, no-challenge error. Add the
solver attribution to `NOTICE`.

### M4 — D: upstream proxy and UDP associate

**T4.1 `feat: honor the upstream proxy for the edge`**
Files: `internal/engine/upstream_proxy.go` (new),
`internal/engine/upstream_proxy_test.go` (new), `internal/engine/connect.go`,
`internal/engine/engine.go`, `internal/upstream/session.go`,
`internal/upstream/session_test.go`, `internal/settings/settings.go`,
`internal/settings/settings_test.go`.
Interfaces: `upstream.Options` gains
`DialContext func(ctx context.Context, network, addr string) (net.Conn, error)`
and uses it (then `Dialer`, then `net.Dialer`) for the edge TCP connection.
`newProxyDialer(rawURL string, base *net.Dialer, logf …) (*proxyDialer, error)`
parses once; `DialContext` dials the proxy through `base`, then:
- `socks5://`/`socks5h://`: greeting (with user/pass when set), CONNECT with the
  hostname as ATYP domain (IP literals as IPv4/IPv6), parse the reply.
- `http://`: `CONNECT host:port`, `Proxy-Authorization: Basic` when set, require
  `200`, preserve any buffered bytes.
Both send the hostname unresolved (remote resolution; socks5 and socks5h behave
identically, documented).
Behavior: `Validate` restricts `upstream_proxy` to `socks5`, `socks5h`, `http`
with a host. `upstreamOptions` returns `(upstream.Options, error)`; when a proxy
is set and `edge_address` is empty it skips `resolveEdge` (no local DNS leak) and
leaves `PinnedIP` empty; with `edge_address` the pinned IP is sent while SNI and
`:authority` keep the hostname. Only the edge dial is proxied; control plane and
DoH stay on the marked direct dialer.
Verification: `go test ./internal/engine/ -run UpstreamProxy;
go test ./internal/upstream/ ./internal/settings/` — in-process SOCKS5/HTTP
proxies record the host and auth; a base dialer that only reaches the proxy
proves no edge resolution; pinned-IP case; scheme rejection; auth failure.

**T4.2 `feat: answer dns over socks udp associate`**
Files: `internal/socks/udp.go` (new), `internal/socks/socks.go`,
`internal/socks/udp_test.go` (new), `internal/dns/dns.go`,
`internal/dns/dns_test.go`, `internal/engine/connect.go`,
`internal/engine/connect_test.go`.
Interfaces: `socks.Server` gains
`Resolve func(ctx context.Context, req *mdns.Msg) (*mdns.Msg, error)`; nil keeps
today's command-unsupported refusal. `startTunnel` builds one
`dns.NewResolver(c.openStream, …)` before the full/proxy-only branch, passes
`resolver.Resolve` to SOCKS, and full mode starts its listener with
`dns.NewWithResolver(resolver)` — one cache and one suppression map for both.
Behavior: UDP ASSOCIATE is accepted for target port 53 or 0 (the request target
is the client's expected source, per RFC 1928); bind `127.0.0.1:0`, reply with
the bound IPv4 address/port; one active association per client IP (a second is
`not allowed`); close the UDP socket when the TCP control connection closes or
the server stops. Datagrams: validate RSV=0/FRAG=0, source IP must equal the TCP
peer (and the port when the request named one), destination port must be 53;
parse the DNS message, resolve with an 8 s context; on resolver error answer
SERVFAIL; drop malformed/non-DNS/foreign datagrams with a debug log. Limits:
32 in-flight (`go` only when a slot is free), 64 KiB messages, no non-DNS UDP.
Verification: `go test ./internal/socks/ ./internal/dns/ ./internal/engine/` —
associate/reply shape, query/response, foreign source, wrong port, FRAG≠0,
in-flight cap, SERVFAIL, cleanup, proxy-only mode wiring, nil resolver refusal.

## Dependencies and ordering

- M0 gates every feature (settings surface, wire fields, TUI viewport, GUI rows).
  M0's keys are inert until their consumer lands; that is intentional and the
  hints describe the final behavior.
- T1.1's `Resolver` is reused by T4.2's UDP relay. T1.1 must land before D.
- M2 lands before M3 so the solver inherits fragmentation, and before M4 so the
  split wrapper composes with the proxy dial (wrap the final conn, after the
  proxy hop).
- T1.3's `OnChallenge` signature is the one T3.2 wires; do not change it twice.
- M4 and M5 are independent of each other; both depend on M1's resolver and
  M2's wrapper. M6 is independent. M7 depends on all code tasks.
- Every commit is self-contained and green; no task depends on a later one
  except where stated.

## Risks and rollback

- **Fastly solver breaks on a page change** → feature-flagged
  (`solve_challenges=off`), fixtures, caps, clear errors; no captcha attempts.
- **TLS fragmentation is defeated by TCP coalescing** → separate writes with
  `TCP_NODELAY` on the dial; off by default; best-effort documented.
- **Upstream proxy leaks DNS** → the connect path skips `resolveEdge` whenever a
  proxy is set; tests assert only the proxy is dialed.
- **HTTP proxy port conflicts** → connect fails with a clear message; the
  setting is off by default.
- **UDP associate becomes a relay** → DNS-only, loopback, source validation,
  32 in-flight, 64 KiB; a nil resolver keeps the old refusal.
- **Disk cache serves a stale list** → fallback only, refreshed on success,
  corrupt files removed; deleting the file is a safe rollback.
- **Additive `SettingsView` fields break an old client** → optional JSON fields,
  no existing field changes; old clients ignore them.
- **Sign-out wipe vs disconnect totals** → the test distinguishes logout from
  disconnect.
- **Rollback of a whole workstream** → each commit is independent; turning the
  setting off restores the previous behavior; the cache and jar are
  disposable; no protocol or schema migration exists.
