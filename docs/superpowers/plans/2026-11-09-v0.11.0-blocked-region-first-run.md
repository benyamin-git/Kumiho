## 1. Pass file, reuse and `bootstrap_required`

Files: `internal/settings/settings.go`, `internal/engine/passfile.go` (new),
`internal/engine/connect.go`, `internal/engine/watchdog.go`,
`internal/engine/engine.go`, `internal/api/api.go`.

- Add `Store.PassPath()` = `pass.json` beside `tokens.json`.
- New `passFile` JSON `{token, expires_at, account_id, prepared_at}` with
  load/save/delete helpers. Save uses `settings.WriteFileAtomic(..., 0o600)`;
  load rejects a missing, malformed, expired, or wrong-account file by
  deleting it. No token is logged or returned.
- `Controller.Start` loads a valid pass for the active account into `c.pass`,
  so `Snapshot().PassExpires` survives a daemon restart.
- Add `Controller.cachedPass()`: in-memory pass first, then the file, and
  return it only while more than 60 seconds remain.
- `Connect` and `redialOnce` use `cachedPass()` before `acquirePass`; a
  successful normal fetch and every renewal persist the pass. `Prepare`
  persists last.
- Add `api.CodeBootstrapRequired = "bootstrap_required"`. When `Connect`
  cannot fetch a pass and a pass file existed for the active account (expired
  or deleted after a previous prepare), return
  “The prepared pass expired. Open Blocked region and prepare again.”
  A never-prepared user keeps `region_blocked`.
- Delete the pass file on logout, account switch/removal, and startup cleanup
  when the account no longer matches.
- Tests: pass-file round trip, 0600 mode, expiry/account rejection, 60-second
  reuse boundary, connect reuse without network, redial reuse,
  `bootstrap_required` versus `region_blocked`, logout deletion.

## 2. `RegionCheck` and `Prepare`

Files: `internal/engine/region.go` (new), `internal/api/api.go`,
`internal/engine/locations.go` (reuse), `internal/fxa/oauth.go` (reuse).

- `RegionCheck(ctx) api.RegionCheckResult`: six unauthenticated GETs in
  parallel with 5 s per host and a 20 s overall context:
  `api.accounts.firefox.com`, `oauth.accounts.firefox.com`,
  `profile.accounts.firefox.com`, `vpn.mozilla.org`,
  `firefox.settings.services.mozilla.com`, `accounts.firefox.com`.
  451 = `blocked`; any other response = `reachable`; transport error =
  `unknown`. Report per-host status, blocked hosts, `browser_blocked`, and
  `relay_configured` (URL and token). Use the direct (non-relay) transport so
  the probe measures the region, not the relay.
- `Prepare(ctx) api.PrepareResult`: reject connected, require sign-in,
  `Locations(ctx, true)`, fetch the FxA profile, then `acquirePass`, then
  write the pass file. Return expiry, quota, server/profile refresh flags,
  and `relay_used`. Never return the token.
- Tests: mock servers asserting the 451/200/timeout classification, the
  parallel deadline, prepare order (pass last), prepare refusals, and the
  no-token payload.

## 3. Runtime control-plane dialer

Files: `internal/engine/connect.go`, `internal/engine/socks` (client).

- Keep `controlPlaneDial` returning the wrapper, but choose the hop per dial:
  while `c.socksSrv` is non-nil, dial the target through the local SOCKS5
  listener with remote name resolution and the marked bypass dialer as the
  hop base; otherwise use the bypass dialer directly.
- The relay transport stays outside, so while connected the order is tunnel
  then relay on 451; while disconnected it is direct then relay.
- Apply TCP_NODELAY and `tlsplit` to the returned connection as today.
- Tests: a fake base records the hop; connected dials the SOCKS address,
  disconnected dials the target; a 451 through the tunnel retries through the
  relay; disconnect restores the direct hop without rebuilding clients.

## 5. CLI and doctor

Files: `internal/cli/cli.go`, `internal/cli/prepare.go` (new),
`internal/cli/guide.go` (new), `internal/cli/connect.go`,
`internal/doctor/doctor.go`, `internal/daemon` (via the API).

- `kumiho prepare [--json]`: calls `prepare`, prints expiry, quota and
  server count; `--json` prints the raw result.
- `kumiho guide`: prints the Blocked region steps (other VPN first, relay
  second) and the relay commands; no daemon needed.
- `kumiho connect` on `region_blocked`/`bootstrap_required` adds the
  `kumiho prepare` and `kumiho guide` guidance.
- `doctor` reachability: a 451 is a warning (“blocked by region”) with the
  guide remediation, not reachable. Add the six-host region summary.
- Tests: command parsing, JSON output, guidance on the two error codes, the
  451 classification.

## 6. TUI

Files: `internal/tui/tui.go`, `internal/tui/settings.go`,
`internal/tui/region.go` (new), `internal/cli/tui.go`.

- Region errors render with the warning tone, not the green notice tone.

- Tests: Enter opens/closes the modal, the countdown text, the warning tone,

`onboarding.js`, `settings.js`, `dashboard.js`, `index.html`.

- Tests: bridge action acceptance, controller region/prepare projection,
  router route, guide render with a mocked blocked result, countdown.
