# v0.11.0 Android design language — Design Spec

**Status:** Approved
**Date:** 2026-11-05

> Roadmap: [2026-10-23-v0.6.0-roadmap-design.md](2026-10-23-v0.6.0-roadmap-design.md).
> This spec replaces the roadmap's v0.11.0 and v0.12.0 rows; the roadmap is
> amended in place by the same docs change.

## Objective / why

The Android app is the best-looking Kumiho client, but it is flat: a plain
filled circle for the one primary action, a stack of hairline cards on every
screen, no drawing anywhere, and no identity beyond the launcher icon. This
release turns it into a deliberate design language — a gauge that shows real
session data, restrained light and motion, a launch wordmark, and a documented
set of tokens and rules — and audits the phone flows that still cause friction.
The result is the reference UI for Kumiho v1.0: every later client, starting
with the Windows GUI, is an adaptation of this design rather than a separate
exploration.

## Success criteria / definition of done

1. The dashboard hero is a single gauge: the power control, a quota arc, and a
   live throughput trace, with the state word and the current down/up rates.
   It renders honestly in every phase — loading, off, connecting, connected
   with quota, connected without quota, proxy-only, error, permission needed —
   and never shows a value the engine did not report.
2. The rates under the gauge match the engine's 2 s status pushes; the gauge's
   content description and state description expose the same facts to
   TalkBack, so the graph is never the only signal.
3. The throughput trace draws the last 60 s: download as a filled area, upload
   as a stroked line, both in one accent. It is empty before two samples, stops
   when the session ends, and holds nothing after the process dies.
4. The quota arc equals `remaining / limit` when both are reported; when quota
   is unknown the arc is an empty track and the label says **Quota unknown**.
5. Diagnostics shows a live throughput graph for the current session and a
   latency chart built from the engine's cached round trips. Nothing is written
   to disk and no new ping is started by opening the screen.
6. Motion: the arc sweeps while connecting and settles on connect; a slow glow
   breathes only while connected and the app is foreground; phases cross-fade;
   a connect produces one pulse and one haptic. With system animations off,
   every one of these snaps, the glow becomes a steady low glow, and no frame
   clock is kept alive.
7. The wordmark appears on the launch screen on Android 12+ only, drawn from
   Roboto SemiBold outlines and tinted by theme; Android 8–11 keeps the plain
   icon splash. No fox artwork is added inside the app UI.
8. Four new semantic roles — `data-line`, `data-fill`, `data-grid`, `glow` —
   exist in the Go palette for all 18 theme × accent combinations, are exposed
   to Android through the gomobile palette and to the GUI as CSS variables, and
   pass the contrast floor in Light, Dark and OLED.
9. Every phone screen uses the language: Dashboard, Locations, Account,
   Settings, setup, Logs, Diagnostics, Split tunneling, and the sheets. No
   phone screen keeps the old flat treatment.
10. Switching location while connected is one confirmed action: it disconnects,
    selects, reconnects, reports progress, and on failure leaves an honest
    disconnected state with a retry — never a claim that traffic moved before
    it did.
11. Every dashboard failure state has at least one forward action (retry,
    sign in, allow VPN, open Diagnostics, open the exact Android setting); no
    failure dead-ends.
12. The Account screen states, at a glance and without colour alone, which
    account is active, which needs re-authorization, its quota, and what quota
    rotation will do next.
13. The three README phone screenshots are regenerated; the visual review
    covers Light, Dark, OLED and one non-blue accent on the emulator.
14. `docs/design.md` exists as the platform-neutral **Kumiho Design Language**,
    and `AGENTS.md`'s Design record points at it.
15. Gates: `make lint && make test && go test -race -count=1 ./... && make
    build`, the Windows/Android cross-builds, `make android-test`, the phone
    connected suite, the new unit tests, and the screenshot review.
16. v0.11.0 ships: the tag builds signed APKs into a draft, the user smoke-tests
    phone and TV, the draft is published as latest, and the stable download
    links resolve.

## Scope

### In scope

- The gauge hero: quota arc, throughput trace, state ring behaviour, glow,
  current rates, and honest degradation.
- Four new palette roles in Go, with the Android mapping and GUI CSS surface.
- Canvas-drawn charts: the dashboard gauge, the Diagnostics throughput graph
  and latency chart.
- Motion: arc sweep, breathing glow, phase transitions, connect pulse and
  haptic, all reduced-motion aware.
- The launch wordmark and its vector asset.
- Visual restyling of every phone screen and shared component: cards, rows,
  chips, inputs, sheets, empty/loading/error states.
- UX reworks in three approved areas: switch location while connected,
  recovery paths, account clarity.
- A full phone UX audit recorded in the implementation plan, with each finding
  marked fixed-in-this-release or deferred with a reason.
- `docs/design.md`, `docs/android.md`, README, CHANGELOG, AGENTS.md, roadmap
  amendment, screenshot regeneration and release prep.
- The tag, the draft release, and publishing it after the user's phone/TV
  smoke test.

### Non-goals (explicitly out)

- Any Android TV UI change. TV keeps its approved ten-foot design and adopts
  the language in a later, separate plan; the design doc records the intent.
- Shell or navigation restructuring: five destinations, bottom bar/rail, the
  More sheet and the More routes stay.
- A materials overhaul: no new elevation model, no blur, no gradients beyond
  the one primary glow, no drop shadows.
- Settings findability (search, regrouping, Advanced relocation), setup
  restructuring or consent persistence, and a Diagnostics/Logs flow rebuild —
  recorded as follow-ups, not built here.
- New settings keys, IPC/protocol changes, engine behavior changes, migrations
  or persisted telemetry.
- Language and RTL (v0.13.0), desktop polish and the Windows GUI redesign
  (v0.12.0), auto-update and the APK installer.
- New third-party dependencies, new typefaces, Material You / dynamic colour,
  or any fox illustration inside the app.
- Widget, tile or notification redesign; they keep their current layouts and
  only inherit tokens automatically.

## Architecture

### Design language

`docs/design.md` defines the language in platform-neutral terms: the role
names, the gauge anatomy and geometry, the motion values, the wordmark, the
component patterns and the accessibility rules. It states which parts are
portable (tokens, gauge rules, motion, chart encoding) and which are
Android-specific (bottom bar/rail, RemoteViews widgets, splash API). It
explicitly records that TV and the Windows GUI are adaptations scheduled
later, not second systems.

### Palette

`internal/gui/theme` gains four roles alongside the existing 25, emitted for
every theme and accent:

| Role | Meaning | Derivation |
| --- | --- | --- |
| `data-line` | The stroke of a data trace | the accent's `primary` |
| `data-fill` | The filled area of a data trace | `primary` at the chart-area alpha, pre-composited on `surface-container` |
| `data-grid` | Axis and grid lines | `outline` at the grid alpha, pre-composited on the chart surface |
| `glow` | The hero glow | `primary` at the glow alpha, pre-composited on `background` |

The values stay six-digit hex so the same string is valid in CSS and in
Compose. The pre-composite rule is documented next to each role; a chart or
glow that sits on a different surface must derive locally instead of reusing
the token. Android's `PaletteMapping.roleNames` and `KumihoColors` gain the
four properties with no fallbacks, and the GUI's `Palette` output gains the
four CSS variables. The GUI uses none of them yet; the Windows port consumes
them later. The existing GUI CSS tests are updated to the new exact strings.

### Gauge

`KumihoGauge` is a Compose Canvas component with three layers, outermost to
innermost:

1. the quota arc — a track and a fill at `remaining / limit`, empty when the
   fraction is unknown;
2. the state ring — the arc itself sweeps indeterminately while connecting or
   reconnecting, then settles to the quota position on connect;
3. the throughput trace — a 60 s polar trace inside the arc, download as a
   filled band and upload as a line, both `data-line`/`data-fill`.

The power button remains the touch target and sits at the centre with the
power glyph; the state word sits beneath, then the current rates, then the
existing **Connect options** entry point. The gauge has a minimum 48 dp touch
target and a content description that names the state, the location and the
rates; the arc and trace are decorative to accessibility, never the only
carrier of meaning.

A pure Kotlin `RateBuffer` holds the last 30 samples (60 s at the engine's 2 s
cadence) in memory, is fed from `DashboardState.status.rates`, clears when the
phase leaves the connected family, and survives rotation only as long as the
holder does. It is JVM-tested: window trimming, gap handling, reset.

### Charts and Diagnostics

The Diagnostics screen gains two charts above the check list: the same
throughput buffer rendered full-width with axes, and a horizontal latency
chart built from the engine's cached round trips. The latency chart reads the
cached locations reply without starting a ping; when the list cannot be read,
the chart is replaced by an honest line, never an empty axis. Neither chart
persists anything.

### Motion

`Motion.kt` grows gauge-specific specs in the same reduced-motion wrapper: an
expressive spring for the arc settle, a 6 s glow cycle with a low peak alpha,
a 150–200 ms cross-fade for phase changes, and a single pulse triggered by the
connected transition. The glow suspends when the app is not resumed. The
haptic is one `HapticFeedbackType.Confirm`-class tick on a successful connect,
never on failure. With system animations off, every animated value snaps; the
glow settles at a steady low alpha rather than disappearing, so the gauge keeps
its shape.

### Brand

`res/drawable/ic_wordmark.xml` is a vector of **Kumiho** set in Roboto
SemiBold with open tracking, tinted from `on-surface` for light and dark
splashes. The splash themes gain `windowSplashScreenBrandingImage` on API 31+;
pre-31 keeps the current icon-only splash. No fox artwork enters the app; the
launcher icon and TV art are unchanged.

### UX reworks

**Switch location while connected.** Tapping a location while a tunnel is live
opens a confirmation naming the target and warning that the current session
ends. Confirming runs disconnect → select → connect through the existing
engine commands, with a progress state on the dashboard and the target
location named. Success shows the new location; failure leaves the app
disconnected, preserves the engine's words, and offers Retry and Diagnostics.
Under lockdown the confirmation also warns that the phone loses network until
the new session is up. Proxy-only sessions use the same choreography.

**Recovery paths.** Each dashboard failure maps to a primary forward action:
Retry for transient connect and refresh failures; Sign in for
`not_signed_in`; Allow VPN for `permission_needed`; Open Diagnostics and Logs
as secondary actions for errors with a technical cause. A live tunnel is never
replaced by an error because a status refresh failed. Errors keep the engine's
wording.

**Account clarity.** The active account carries a text **Active** chip; an
account needing re-authorization carries a **Re-authorize** chip and action;
quota reads **N% left** or **Quota unknown**; the rotation card names which
account is active and what the threshold will do. Sign-out actions keep their
current confirmations and gain a one-line consequence sentence.

### Accessibility

All three themes and every accent are checked: body text at least 4.5:1, the
gauge's numbers visible as text, the state carried by word and icon as well as
colour, 48 dp targets, TalkBack labels on every new control, charts summarised
in words, and the glow never the sole indicator of connection. Focus order is
unchanged; TV focus work is untouched.

## Risks + rollback

| Risk | Mitigation |
| --- | --- |
| The gauge looks busy or cheap in one theme | Screenshot review in Light, Dark, OLED and one accent before acceptance; the empty-arc and no-trace states are designed, not left to chance |
| A continuous glow costs battery or causes OLED burn-in | Foreground-only, 6 s low-amplitude cycle, steady under reduced motion, suspended off-screen |
| Custom drawing janks on low-end phones | No allocation in draw, one buffer, no library, frame review on the emulator; the trace is optional and degrades to numbers |
| New palette roles break the GUI CSS tests or drift from the house rules | Roles are additive, covered by a palette test in Go and an Android mapping test |
| Pre-composited role values look wrong on another surface | The rule is documented; consumers that leave the documented surface derive locally |
| Switch-location under lockdown leaves the phone offline | The confirmation warns before acting; failure states are honest and offer Retry |
| Splash branding is inconsistent on Android 8–11 | Accepted and documented; no in-app frame is added |
| The T3 emulator/Gradle override disturbs the running service | Explicit approval recorded; Gradle and emulator runs are batched, never concurrent with service work |
| The draft is published before it is tested | Publishing waits for the user's phone and TV smoke test |

Rollback is a revert of the release commits. No migration is involved: the
palette roles are additive, no setting is added, no stored data changes, and
the app degrades to the previous UI if the release is rolled back.

## Dependencies / ordering

1. Go palette roles first — Android and the GUI cannot reference them until
   they exist.
2. `docs/design.md` and the AGENTS.md Design record before the screen work, so
   the screen work argues from a written language.
3. Gauge and `RateBuffer` before Diagnostics, which reuses both.
4. Motion after the gauge exists, because the arc sweep is the state ring.
5. Splash wordmark independently of the screens.
6. UX reworks independently of the visual rollout, but before the final
   screenshots.
7. Screenshots and docs last; release prep after all gates.
8. Publishing after the user's device smoke test.
