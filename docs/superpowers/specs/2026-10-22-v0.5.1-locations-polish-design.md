# v0.5.1 Locations Polish — Design Spec

**Status:** Approved
**Date:** 2026-10-22

## Objective / why

v0.5.1 is a small, client-only release that makes Kumiho's locations easier to
scan and compare. Country rows gain their ISO flag in every client, a new
`Ping all` action measures the whole loaded server list instead of only the
currently visible rows, and one `Expand all` / `Collapse all` control opens or
closes every country and city at once. The Android app, Windows GUI and Linux
TUI all receive the same three changes; the daemon, engine, control protocol
and mobile facade are untouched.

The outcome matters because the locations list is the one screen where users
choose a route by country and compare latency. Flags improve recognition at a
glance; Ping all makes a full-list comparison one action; the expansion toggle
turns a deep tree into a one-click overview.

## Success criteria / definition of done

1. Android Locations country rows, the Android connect-sheet country rows and
   the Android current-selection summary show the correct ISO flag emoji;
   `Recommended`, blank codes and codes that are not two ASCII letters show no
   flag.
2. The Windows GUI Locations tree and the GUI dashboard location `<select>`
   show the same flag; the TUI Locations country rows show it too.
3. Flags are decorative on custom surfaces: GUI tree flags are `aria-hidden`,
   Android custom rows keep the country name as the accessibility label, and
   the TUI needs no equivalent. The native GUI `<select>` is the one accepted
   exception: its option text includes the flag.
4. `Ping all` probes every non-quarantined, connectable server in the loaded
   list, deduped by `host:port`, regardless of filter or expansion. `Test
   speed` keeps its existing visible-row behavior (and its 16-host cap in the
   GUI).
5. While Ping all runs, the GUI status line, the Android button and the TUI
   footer show a static target count; no cancel is offered. Test speed and Ping
   all cannot run at the same time.
6. One `Expand all` / `Collapse all` control exists on Android and in the GUI;
   `x` does the same in the TUI. The label reflects the action, both countries
   and cities are affected, and the control is unavailable while a filter is
   active.
7. No engine, IPC, daemon or mobile-facade change; control protocol v1 stays
   byte-compatible.
8. Go and Kotlin unit tests cover the flag mapping, the Ping-all target set and
   the expansion toggle; the Android Compose tests and the TUI tests cover the
   new controls.
9. README, `docs/gui.md`, `docs/android.md`, `docs/usage.md`, `AGENTS.md` and
   `CHANGELOG.md` describe the shipped behavior; the Android default version is
   `0.5.1` (`versionCode` 501); the GUI/TUI screenshots are regenerated.
10. `make lint && make test && go test -race -count=1 ./... && make build` and
    the Android unit/lint/assemble gate pass.

## Scope

### In scope

- Country-flag derivation and presentation in the three clients.
- `Ping all` in the Android Locations screen, the Windows GUI Locations screen
  and the TUI Locations screen.
- A single `Expand all` / `Collapse all` toggle in the Android and Windows GUI
  toolbars, and the `x` key in the TUI.
- TUI help text and the visible key hints.
- Tests, docs, changelog, README status, version default and screenshot
  regeneration for v0.5.1.

### Non-goals (explicitly out)

- The Windows tray Location submenu, the dashboard status card's location row,
  the Android dashboard status card and any other place a country name appears
  outside the four in-scope surfaces.
- Flags on city rows, server rows or the `Recommended` pseudo-country.
- New protocol commands, a ping-cancel command, progress streaming beyond the
  static target count, or server-side concurrency changes.
- Changing Test speed's visible-row rules or the GUI's 16-host cap.
- Persisting expansion state across screens or app restarts.
- Translating the new copy; all three clients remain English-only.
- Publishing, tagging or opening a release PR for v0.5.1.
- Any redesign of the locations screens beyond these three additions.

## Architecture

### Flag derivation

- **Go:** `internal/serverlist` gains a small presentation helper that trims and
  uppercases a code, returns `""` for `REC`, blank or anything that is not two
  ASCII letters, and otherwise maps the two letters to regional-indicator
  symbols (`U+1F1E6 + letter - 'A'`). The TUI consumes it directly; the GUI
  controller is not changed because the web UI formats in JS.
- **JS:** a new shared module under `internal/gui/web/static/js/` exports one
  function with the same rules. `locations.js` and `dashboard.js` import it.
  A flag is prepended with a single space only when non-empty.
- **Kotlin:** a small object under `android/app/src/main/java/dev/benyamin/
  kumiho/ui/locations/` implements the same rules. Compose uses `clearAndSet
  Semantics { contentDescription = countryName }` (or the equivalent row
  semantics override) on the combined visible text so TalkBack announces only
  the country name. The GUI tree's flag span is `aria-hidden="true"`; the
  native `<select>` option text includes the flag, as accepted in D5.

### Locations presentation

- **GUI:** `locations.js` renders `🇩🇪 Germany (DE) · 1 city` in country rows
  and controls the new buttons. `dashboard.js` prefixes the country options
  in the existing native `<select>`. The actions row order is Refresh, Test
  speed, Ping all, Expand all/Collapse all.
- **Android:** `LocationsScreen` gets a second action row with `Test speed`,
  `Ping all` and `Expand all`/`Collapse all`; row 1 keeps Refresh and replaces
  the old helper with `X visible · Y total`. The connect sheet's country rows
  and the selection summary prefix the country name. Cities, servers and
  `Recommended` stay unprefixed.
- **TUI:** `renderLocations` prefixes country names. The help line and footer
  add `x expand/collapse all` and `P ping all`.

### Ping all

- Every client derives the same target list from its loaded tree: all
  countries, all cities, skip quarantined servers, skip entries without a
  usable connect target, dedupe by `host:port` (case-insensitive key), and
  keep the first spelling. The GUI reuses `connectTarget`, the TUI reuses
  `ConnectTarget`, and Android reuses the address rule already used by Test
  speed.
- The existing `ping` IPC command carries the whole list; the daemon's 24-way
  worker pool streams one `ping_result` per host. The mobile facade already
  streams through `OnPing`. No protocol change is needed.
- Test speed and Ping all share one run state. Starting one while the other is
  running is ignored; both buttons are disabled until the run's window closes.
- The run window is `max(base, ceil(N / 24) × 1.5 s + margin)`; clients show the
  target count for the whole run and fill latency labels as results arrive.
  Unreachable targets receive a `timeout` result, so every requested host
  settles.
- GUI status text: `Pinging 35 servers...` (the existing status line's tone and
  ellipsis style). Android button: `Pinging 35…` with a spinner, mirroring
  `Testing…`. TUI footer: `pinging 35 servers...` until the pending set is
  empty. Test speed keeps `Testing speed...` / `Testing…`.

### Expand all / Collapse all

- The toggle operates on the client's stored expansion sets, not on the
  filter-forced view state.
- If any country or city is stored as expanded, the label is `Collapse all`
  and the action clears both sets. Otherwise the label is `Expand all` and the
  action adds every country code and every `country/city` key.
- GUI and Android disable the control while the filter/search field is
  non-empty; the TUI ignores `x` while its trimmed filter is non-empty.
- The control is also disabled while there is no loaded tree, and it does not
  touch the selection or the current cursor.

### Constraints

- No engine, `internal/ipc`, `internal/daemon`, `internal/api` or `mobile/`
  changes. No new protocol fields or settings keys.
- The GUI remains a client of the same state projection; the web assets stay
  self-contained (no network fonts or images).
- Android remains English-only and keeps its existing type scale, spacing,
  touch targets and theme tokens.
- The TUI's `p` behavior and all existing keys stay unchanged.

## Risks + rollback

- **Windows flag fallback.** Windows 11 renders country-flag emoji as two
  regional-indicator letters. This is accepted by D2; the country code already
  follows the name, so the row stays readable.
- **House-style departure.** Emoji in UI chrome violates the design skill's
  Ban 3. The user explicitly requested it, and the consequence is visible on
  Windows. The spec and `AGENTS.md` record the departure.
- **Multiple colors on one screen.** Flags are data, not accents; they do not
  change the active accent, buttons or status colors.
- **Terminal width.** Flag emoji are wide and may be two columns per regional
  indicator in some terminals. Country lines are not column-aligned, so no
  layout depends on their width; the TUI screenshot is the visual check.
- **Long ping runs if the list grows.** The dynamic window and disabled
  buttons keep the UI honest, but there is no cancel. Ping all on today's
  35-server list is ~3 seconds; a much larger list would take longer. Adding
  cancellation would require new protocol surface and is out of scope.
- **Screenshot dependency.** The committed GUI/TUI captures need a color
  emoji font. The plan installs `fonts-noto-color-emoji` and documents it as a
  prerequisite; without it, the captures show the same fallback letters as
  Windows.
- **Rollback.** All changes are additive and client-local. Revert the UI
  commits to restore v0.5.0 behavior; there is no data migration, no protocol
  change and no persisted state to clean up.

## Dependencies / ordering

1. Flag helper + unit tests (Go, then Kotlin, then JS shared module).
2. TUI locations changes and tests.
3. GUI locations and dashboard changes plus the visual capture.
4. Android locations, connect-sheet and summary changes plus tests.
5. Docs, changelog, README, version default and screenshot regeneration.
6. Full Go and Android gates.

Each step is an independently verifiable, commit-sized unit; the Go gate must
stay green after every commit.
