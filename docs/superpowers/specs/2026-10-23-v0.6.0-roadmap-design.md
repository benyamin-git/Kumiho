# Kumiho Roadmap v0.10.0–v0.12.0 — Design Spec

**Status:** Approved
**Date:** 2026-11-05 (rewritten; this file was first written on 2026-10-23 as the
v0.6.0–v0.14.0 roadmap)

**Scope:** the three remaining planned releases. Shipped history is kept as a
compact table for context. No release is designed in detail here; each gets its
own spec and plan before code starts.

## Objective / why

The old roadmap carried nine releases and two speculative themes nobody asked
for at this point. The remaining work is now three releases the user actually
wants: Android polish, desktop polish with a Windows GUI redesign, and Persian
support with RTL. DNS privacy and smart routing are removed from the plan
entirely, so later specs cannot inherit them by accident.

## Success criteria / definition of done

1. v0.10.0, v0.11.0 and v0.12.0 ship in that order; each release is
   independently usable and verifiable.
2. Every release has its own approved spec and implementation plan before code
   starts. Later releases are not implemented early.
3. A release depends only on earlier releases listed in its "Depends on" row;
   no forward dependencies.
4. Existing settings, control-protocol v1 payloads and user data keep working.
   New fields and commands are additive.
5. Language support ships last (v0.12.0) and covers the Windows GUI and Android
   only; the TUI and CLI stay English.
6. No release is tagged, pushed or published without an explicit request.
7. DNS privacy and smart routing do not appear in this plan; git history is
   their only record.

## v0.10.0 — Android polish

**Goal.** Close the remaining Android gaps before any desktop or language work
starts, without touching routing or DNS.

**In scope**

- 1×1 connect-toggle and 2×1 status-plus-toggle home-screen widgets, sharing
  state with the Quick Settings tile, using immutable PendingIntents. Phone
  only; Android TV has no home-screen widgets.
- Suppress AAAA answers in the in-tunnel resolver: no AAAA records, no FakeDNS,
  IPv6 stays blackholed.
- Make the existing 25 s keepalive profile the Android default. No wake lock;
  users can still switch back with `keepalive_profile`.
- Bundle GlobalSign Root R46 and merge it with the system pool used for edge
  dials. Root E46 is already shipped in `internal/upstream/roots/`.

**Non-goals.** No smart routing, no DNS or blocklist work, no desktop changes,
no language support, no TV widget, no new permission model.

**Approved exceptions (2026-11-05).** Two changes reach beyond Android because
the engine has no Android-only seam: AAAA suppression applies on every
platform, and `keepalive_profile = "slow"` becomes the engine default on every
platform. Both are recorded in
[the v0.10.0 spec](2026-11-05-v0.10.0-android-polish-design.md); the rest of
this roadmap is unchanged.

**Acceptance.** Go gate; Android JVM, lint and assemble; the phone emulator
suite (and the TV suite for regressions); widget state tests; resolver tests for
AAAA suppression; a fingerprint test for the added root. Automated gates only.

## v0.11.0 — Desktop polish and Windows GUI redesign

**Goal.** Make the desktop clients update, fit real networks and look coherent
without manual setup.

**In scope**

- Verified update flow: daily stable check, 7-day snooze, manual check, download
  the artifact, verify the published SHA-256, then prompt. Linux never
  auto-installs as root; Windows runs the installer; Android opens the APK
  installer. Stable channel only, no silent install.
- System proxy automation on Windows (WinINET/WinHTTP) and GNOME (gsettings),
  saving and restoring the previous setting.
- Trusted-network autoconnect rules on Linux and Windows; wired networks are
  trusted by default; no metered auto-connect unless allowed.
- Windows GUI redesign and cleanup. At roadmap level this is intent only: the
  v0.11 spec decides layout, navigation, density, copy and any code
  restructuring.
- Fix the known divergence where applying a theme reloads to the Dashboard
  instead of the screen the user was on (`docs/windows-testing.md`).

**Non-goals.** No macOS, no silent install, no beta channel, no new Android UI
beyond the APK-installer handoff, no DNS or routing work, no language support
(that is v0.12.0).

**Acceptance.** Go gate; Windows cross-build; update-check and checksum tests;
proxy save/restore tests; network-rule tests; Android CI gate for the
APK-installer handoff; GUI screenshots regenerated through the web harness.
Automated gates only.

## v0.12.0 — Language and RTL

**Goal.** Ship a native Persian experience on the surfaces where it matters.

**In scope**

- English default; Persian selectable in the setup wizard's first step and in
  Settings.
- Full RTL layout on Android (phone and TV) and the Windows GUI.
- Every user-facing GUI/Android string localized: screens, errors,
  notifications, widget and tile labels.
- Persian translations drafted by the agent and reviewed by the user; English
  remains the source of truth.

**Non-goals.** No TUI/CLI localization, no additional languages, no docs
translation, no new features.

**Acceptance.** Go/Android gates; string-coverage test; RTL layout tests; user
translation review before tagging.

## Architecture

This roadmap defines no runtime components or interfaces. Each release spec
owns those. The delivery structure is:

- **Release records.** Each release gets `docs/superpowers/specs/<date>-<topic>-design.md`
  and `docs/superpowers/plans/<date>-<topic>.md`, approved in that order. The
  roadmap links to them as they are written.
- **Delivery.** Implementation lands on `main` as one logical commit per task;
  every commit leaves the gate green; the tag is cut only on request at release
  time.
- **Dependency graph.** v0.10.0 and v0.11.0 both build on the shipped v0.9.3
  baseline; v0.11.0 is ordered after v0.10.0 by choice, not by dependency;
  v0.12.0 follows because it must translate final strings.
- **Compatibility.** Control protocol v1 stays byte-compatible; new fields and
  commands are additive; no user data migration is planned by this roadmap.

## Risks + rollback

| Risk | Mitigation / rollback |
|---|---|
| The GUI redesign grows without bound | Roadmap records intent only; the v0.11 spec fixes layout, navigation and cleanup scope before code starts |
| The update flow touches installers and privileges | No silent install, Linux never auto-installs as root, SHA-256 verified, stable channel only, `auto_update` can be turned off |
| Proxy automation strands a machine on a dead proxy | Save the previous value and restore it on disconnect and on failure; covered by tests |
| Trusted-network autoconnect connects on a hostile network | Wired trusted by default, metered blocked unless allowed, per-network rules are explicit |
| Persian translations ship unreviewed or half-finished | English is the source of truth; user review is part of the release gate |
| Scope creeps back toward DNS or routing | Those themes are deleted; a new spec would require an explicit roadmap change |
| A release slips and blocks later ones | Releases are independent except where the dependency table says otherwise; later work waits |

Rollback per release: v0.10.0 changes no setting surface; v0.11.0 can be
neutralized with `auto_update = off` and by disabling autoconnect rules;
v0.12.0 falls back to English by setting `language = en` or `system`.

## Dependencies / ordering

1. **v0.10.0** — needs the shipped v0.9.3 baseline only.
2. **v0.11.0** — needs the shipped baseline; ordered after v0.10.0 by choice.
3. **v0.12.0** — needs v0.11.0 because it must translate the final UI strings.

Each release is merged only after its own gate. A slipping release does not
block earlier ones; later ones wait.
