# v0.9.0 Region and Location Truth — Design Spec

**Status:** Approved
**Date:** 2026-10-31

> **Roadmap note (2026-11-05):** the later themes and version numbers in this
> spec were replaced by the
> [roadmap spec](2026-10-23-v0.6.0-roadmap-design.md). v0.10.0 is Android
> polish, v0.11.0 desktop polish and Windows GUI redesign, and v0.12.0 language
> and RTL; DNS privacy and smart routing are no longer planned.

## Objective / why

Ship the five remaining v0.8.0 region-and-location-truth items together with the
browser sign-in fix as one v0.9.0 release. Kumiho should tell the truth about
where it is, what it can reach, and how fast each exit really is: surface HTTP
451 clearly and offer a user-controlled control-plane relay; honor the server
list's JEXL filters and locked flags; measure latency through a real edge path;
and let users pin the locations they actually use. All five clients get the
same surfaces, and the release is the first full release after v0.8.3.

## Success criteria / definition of done

1. The five remaining v0.8.0 items and the A2 browser fix are on `main` and in
   the v0.9.0 release:
   - HTTP 451 classification, control-plane relay, and the Cloudflare Worker
     template.
   - Server-list JEXL (`versionCompare`, `env.country`), `filter_expression`
     and `locked`/`allow_locked`.
   - Real-delay ping through a temporary edge session per candidate, the
     30-minute cache, Ping all, and a selectable Fastest location.
   - Favorites and recents, shared by the engine across clients.
   - Browser sign-in completes end to end with a real account from the CLI
     before the tag.
2. The Go gate is green:
   `make lint && make test && go test -race -count=1 ./... && make build &&
   GOOS=windows GOARCH=amd64 go vet ./... &&
   GOOS=windows GOARCH=amd64 go build ./... &&
   GOOS=android GOARCH=arm64 go build ./...`.
3. The Android and Android TV CI jobs (JVM tests, lint, debug APK, connected
   suites) are green on the pushed commit before tagging.
4. Mock tests cover 451 retry/allowlist/auth behavior, JEXL and locked records,
   ping-cache/TTL/Fastest selection, and favorites/recents persistence. No live
   451 environment is required.
5. Every client shows the new surfaces: Android phone, Android TV, Windows GUI,
   TUI, and the CLI. Locked locations are hidden by default and revealed by
   `allow_locked`; locked rows carry a text-and-icon badge.
6. A real CLI browser sign-in completes after CI is green and before the tag:
   authorization URL, redirect exchange, profile, account list, and
   authenticated daemon status all succeed.
7. `v0.9.0` is tagged and pushed; the release workflow publishes the signed
   Android APKs, desktop assets, `SHA256SUMS`, and formatted release notes.
8. After publication, the user checks the phone WebView sign-in; a failure
   becomes a focused v0.9.1. Android phone/TV screenshots are refreshed in a
   post-release docs commit.

## Scope

### In scope

- Control-plane relay: `internal/relay` retry transport, relay URL/token
  settings, `relay_test` IPC, and the `contrib/relay-worker/` template.
- HTTP 451 handling for the control plane and the edge, with clear terminal
  errors and a settings hint.
- Server-list JEXL subset, `filter_expression` evaluation, `locked` filtering,
  `allow_locked`, and the locked badge/footer action.
- Real-delay ping per candidate through a temporary edge session, a 30-minute
  daemon cache, `ping_done`, cached RTTs in `LocationsResult`, and the Fastest
  row.
- Favorites and recents with country/city/server identity, fallback resolution,
  a five-entry recent cap, and Clear recents.
- Pinned Fastest/Favorites/Recent sections on all Locations surfaces.
- CLI `--favorites` / `--recent` filters, markers, and JSON arrays.
- Settings → Region on every client: `allow_locked`, `relay_url`,
  write-only `relay_token`, and Test relay.
- Docs, changelog, roadmap amendment, screenshots, CI/release verification.
- The A2 browser fix already committed as `ce9d501` and the CLI live proof.

### Non-goals (explicitly out)

- DNS privacy, custom DoH, blocklists, or the v0.10.0 work.
- Android widgets, auto-update, localization, smart routing, or desktop polish.
- Live HTTP 451 testing from a blocked region; mock tests are the acceptance.
- A phone-before-tag gate; the phone WebView check happens after publication.
- Relaying the browser sign-in page or the VPN data plane; the relay is
  control-plane only.
- New third-party Go dependencies; the Worker template is plain JavaScript.
- Changing the control protocol version or the existing envelope/field bytes.
- Reworking the approved flat Locations layout or the existing speed-order
  rules beyond the pinned sections described here.

## Architecture

### Control-plane relay and 451

Add `internal/relay`, a small package that owns:

- `Config{URL, Token string}` with validation. `URL` must be an HTTPS origin:
  no userinfo, path, query or fragment; a trailing slash is normalized away.
  `Token` is optional and never logged.
- `Transport`, an `http.RoundTripper` wrapper. It forwards normally. When a
  response is `451` and a relay is configured, it closes/discards the first
  response body, clones the request body, rewrites the URL to
  `<relay>/<target-host><target-path><target-query>`, sets
  `X-Kumiho-Relay-Token`, and performs exactly one retry. If the retry also
  returns `451`, the transport returns a typed `*BlockedError` carrying the
  status, whether a relay was configured/tried, and the relay error (if any).
  It never retries a request that is already addressed to the relay host.
- A target allowlist (D9) enforced client-side as defense in depth; the Worker
  enforces the same list.
- `Test(ctx, http.Client)` which performs a direct relay request to
  `https://firefox.settings.services.mozilla.com/v1/buckets/main/collections/vpn-serverlist/records?limit=1`
  and returns status/latency.

The engine's three control-plane clients (`c.httpClient`, `c.fxa.HTTP`,
`c.guardian.HTTP`) get the relay transport wrapped around their
`*http.Transport` in `UseBypassDialer`; the wrapper reads the effective relay
configuration atomically, so `settings_set` changes apply without a restart.
The existing cookie jar, TLS fragmentation, anti-bot solver and browser UA are
unchanged.

`BlockedError` maps to `api.RemoteError{Code: api.CodeRegionBlocked
("region_blocked"), Message: ...}` at the engine boundary. The error copy is:

- No relay: “This region is blocking Mozilla's servers (HTTP 451). Set a
  control-plane relay in Settings → Region, or deploy the relay from
  docs/relay.md, then retry.”
- Relay failed: “Mozilla returned HTTP 451 and the configured relay failed:
  <reason>. Check the relay URL and token in Settings → Region.”
- Edge dial 451: “The VPN edge refused this region (HTTP 451). A
  control-plane relay cannot fix the VPN data path; connect from a supported
  region.”

An edge `451` is a `ConnectRejected` from the initial `upstream.Dial` or a
watchdog redial, not a per-target stream rejection. Per-target CONNECT errors
stay with the SOCKS client.

### Relay secret and settings

`relay.token` lives in `filepath.Dir(paths.Tokens)`, mode 0600, with the
directory created 0700. It is written atomically and never appears in
`config.toml`, `state.json`, logs, or `SettingsView`. The daemon reads it at
start and after a `settings_set` for `relay_token`; `reset` deletes it. The
Android facade passes the no-backup tokens path, so the token is excluded from
backup.

`SettingsView` gains `allow_locked`, `relay_url`, and `relay_token_set`; the
token itself is write-only. `settings_set` accepts `allow_locked`, `relay_url`,
`relay_token`; the CLI prompts for the token without echo when the value is
omitted.

`relay_test` is a new IPC command. It returns
`{ok, status, latency_ms, error}`. It tests the relay even when the network is
not currently blocked; it never touches the data plane.

### Server-list truth

`internal/serverlist` gains:

- `Context{FirefoxVersion, Country string}` and `Options{Context, AllowLocked,
  Logf}`.
- A filter evaluator for the Remote Settings JEXL subset:
  - literals (`true`, `false`, strings, numbers);
  - `env.version`, `env.country`;
  - `env.version|versionCompare("...")` with `<`, `<=`, `>`, `>=`, `==`,
    `!=` against a number;
  - `env.country ==/!= "XX"`;
  - `&&`, `||`, `!`, parentheses.
  - Unknown identifiers, transforms, or syntax return an error; the caller
    includes the record (fail open) and logs a debug warning with the
    expression.
- `versionCompare` implements Firefox ordering for numeric components and
  `a`/`b`/`rc` pre-release suffixes; `151.0a1 < 151.0 < 158.0`.
- `ParseWithOptions` evaluates `filter_expression` for each record, skips
  records whose expression is false, applies the locked filter, and preserves
  the existing `CatchAll Anycast` exclusion and quarantine handling.
  `Country` gains `Locked bool` (`json:"locked,omitempty"`).
- The engine keeps the raw payload (or re-parses it cheaply), so toggling
  `allow_locked` or learning the exit country re-filters without a network
  request. `Locations()` returns only visible rows; locked rows appear only
  when `allow_locked` is true.
- `env.country` is `c.exitCountry` when the last exit check succeeded; on a
  fresh daemon or before an exit check it is empty and expressions that need
  it fail open.
- The Firefox version is parsed from `fxa.BrowserUserAgent` (`Firefox/(\S+)`);
  if parsing fails, the context is empty and expressions that need it fail
  open.

The live list has two US records split at `151.0a1`; using `158.0` keeps the
modern record and drops the legacy “CatchAll Anycast” record. Fixtures cover
both, plus locked and malformed expressions.

### Real-delay ping and Fastest

`serverlist.PingTCP` is no longer the production path. The engine owns
`PingHosts(ctx, hosts, emit)`:

1. Deduplicate hosts and resolve each to a visible candidate.
2. Ensure a pass: reuse `c.pass` if it is still valid, otherwise call
   `acquirePass` (which may refresh the access token). Signed-out/invalid
   entitlement is a structured error.
3. For each candidate (bounded to 4 in flight), dial a throwaway
   `upstream.Session` via the existing `upstreamOptions` + `dialUpstream`
   path, then time `OpenStream(ctx, "vpn.mozilla.org", 443)`.
4. Close the throwaway session immediately; record `{rtt, measured_at}` in the
   engine cache keyed by candidate address. A timeout/failure records a nil
   RTT (still cached for 30 minutes).
5. Emit `ping_result` per host as it completes and one `ping_done` with
   `{total, answered}` to the requesting connection.

`PingHosts` never installs the throwaway session as the active tunnel and never
interrupts an active session. The cache is in memory, pruned on each read to
the 30-minute window and the current visible list. `LocationsResult` gains
`latency: { "<host:port>": {rtt_ms, measured_at} }` for fresh entries.

`Fastest` is a client-synthesized pinned row: the clients find the minimum
finite cached RTT in the result. The row is disabled when no fresh finite
result exists, with “Run Ping all to enable Fastest”. Selecting it sends
`select_location` with `fastest: true`; the engine resolves the same minimum
candidate (ties by country/city/host), persists the actual server, and returns
normally. The status checkmark follows that server. The engine also accepts
`fastest: true` on `connect` for a direct call.

`Ping all` measures every visible server (the 2026-10-29 locations spec's D18), skips
quarantined/targetless records and locked records when `allow_locked` is off,
and remains one run at a time per client. No ping starts automatically on load,
search, refresh, resume, or network change.

### Favorites and recents

`internal/settings.State` gains:

```go
type LocationRef struct {
    CountryCode string `json:"country_code"`
    CityCode    string `json:"city_code"`
    Server      string `json:"server"`
}
Favorites []LocationRef `json:"favorites,omitempty"`
Recents   []LocationRef `json:"recents,omitempty"`
```

The engine validates a ref against the current list, resolves the exact server
first, then the first usable server in the city, and drops entries that resolve
to nothing. Favorites are toggled immediately and persisted atomically.
Recents are appended on a successful `Connect` (after the tunnel is up), newest
first, deduplicated by the same resolution key, capped at five. Clear recents
empties the list. Neither list is per-account; both are engine-shared like the
selected location.

New IPC commands:

- `favorite_location` — `{country_code, city_code, server, favorite}`; reply
  `{ok}`. The client toggles optimistically and refetches on error.
- `clear_recents` — empty payload; reply `{ok}`.
- `ping_done` — server event as above.
- `relay_test` — as above.

`LocationsResult` gains `favorites` and `recents` arrays of the refs plus the
`latency` map.

### Locations UI

All graphical clients render the same sections above the flat list:

1. **Fastest** — one row; enabled only with a fresh finite RTT; shows the
   measured RTT; disabled hint otherwise.
2. **Favorites** — rows resolved from the refs, country/city order; each row
   has the trailing star.
3. **Recent** — newest first, max five; header has a **Clear** text action.
4. **Full list** — the existing flat list, Recommended first; existing speed
   order applies only here after a completed Ping all.

Empty sections are omitted. Favorites and recents also remain in the full list
and carry the same star/clock marker. Speed order never reorders the pinned
sections.

- **Android phone**: Compose sections with the existing `KumihoCard`/row
  treatment; 48 dp star icon buttons with content descriptions; locked badge
  with a lock icon and the word “Locked”; the footer action toggles
  `allow_locked` and refreshes; a “Ping all” run shows Pinging N… until
  `ping_done`; a clear action in the Recent header.
- **Android TV**: the same sections and actions, focusable in D-pad order; the
  star button is focusable without stealing the row's select action; TV type
  scale and overscan frame remain.
- **Windows GUI**: listbox sections with real buttons (not divs) for stars and
  Clear; 40 px controls; visible focus ring; accessible labels; the existing
  keyboard shortcuts stay.
- **TUI**: pinned section headings, `*` favorite marker, `~` recent marker,
  `f` toggles the cursor row, `P` Ping all, `r` refresh, `/` filter, Enter
  select, `c` clears recents from the Recent header, `?` help; footer updated.
- **CLI**: `kumiho locations` marks favorites `*` and recents `~`, adds
  `--favorites` and `--recent` filters, and includes `favorites`/`recents` in
  `--json`; `--ping` waits for `ping_done`; existing flags and exit codes stay.
- **Settings → Region** (all clients): `allow_locked`, `relay_url`,
  write-only `relay_token` with Clear, and Test relay. The relay help text says
  it is used only after HTTP 451 and does not proxy the browser sign-in page.

### Error and empty states

- 451 copy as above; the CLI prefixes it with the command name; the GUI and
  Android show the message and a “Open Settings” action where the surface
  supports it; the TUI shows it in the status line with the same text.
- Relay Test: success shows “Relay OK — N ms”; token rejection shows “Relay
  rejected the token”; unreachable shows “Relay unreachable: <detail>”.
- JEXL failures are debug logs only; the user sees the record (fail open).
- Ping all with no candidates shows the existing “No locations to ping”
  notice; a failed pass/token shows a clear “Ping all needs a signed-in
  account” or the underlying quota/token error.
- Fastest with no fresh cache is disabled with the Run Ping all hint; an
  expired cache clears the labels on the next Locations load.
- Empty favorites/recents sections are omitted; Clear recents is hidden when
  empty.

## Risks + rollback

- **Per-candidate probes are heavier than direct TCP.** Bound to 4 in flight,
  10 s per probe, close sessions immediately, cache 30 minutes, and never
  interrupt the active tunnel. A failed run is a notice, not a state change.
- **Relay transport could affect normal requests.** It forwards byte-for-byte
  unless the response is 451; unit tests cover no-relay, one-retry, relay-451,
  body replay, allowlist and token cases. Resetting the relay settings returns
  to the direct path immediately.
- **JEXL fail-open could show unusable servers.** The locked filter still
  applies; unsupported expressions are logged; the user can refresh. Failing
  closed would hide the whole list on a new Mozilla expression.
- **Stale `env.country`.** It only comes from the last successful exit check
  and is never persisted; unknown values fail open.
- **Android screenshots are stale until the post-release docs commit.** D35
  accepts this; the README image paths stay valid.
- **Phone WebView sign-in could still fail after the CLI proof.** D32 accepts a
  post-release check; a failure becomes a focused v0.9.1. The shared OAuth path
  is proven first.
- **Release secrets could be missing.** Verify the five `ANDROID_*` secrets
  before tagging; stop instead of publishing unsigned or failing assets.
- **Tag/release rollback.** If the workflow fails before publication, fix the
  cause and ask before deleting/recreating the tag. Never force-push or amend a
  published tag.
- **State/protocol compatibility.** New state fields and IPC types are
  additive; older clients ignore them and continue to work. Downgrading leaves
  the relay secret and favorites in place.

## Dependencies / ordering

1. `internal/relay`, settings/secret, and 451 classification.
2. `internal/serverlist` JEXL/locked with fixtures.
3. Engine ping cache/probes, `ping_done`, and Fastest resolution.
4. Favorites/recents state and IPC.
5. Client surfaces: CLI/TUI, Windows GUI, Android phone/TV.
6. Docs, changelog, version bump, roadmap amendment.
7. Push `main`, Android CI green, CLI live sign-in proof, tag `v0.9.0`, watch
   the release workflow.
8. Post-release: prompt the phone check; Android screenshots docs commit;
   v0.9.1 if the WebView check fails.

The relay and server-list work are independent of the ping/favorites work; the
UI work consumes the engine/API changes. The release steps are strictly last.
