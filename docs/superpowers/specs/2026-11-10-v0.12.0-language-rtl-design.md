# v0.12.0 Language and RTL — Design Spec

**Status:** Approved
**Date:** 2026-11-10

## Objective / why

Ship a native Persian experience on the Windows GUI and on Android phone and
TV: every user-facing string localized, full right-to-left layout, Persian
digits and Jalali dates, and a first-run language choice. English stays the
default and the source of truth. The language preference is an engine setting
so the GUI and the embedded Android engine share one value.

This release also resolves the roadmap conflict. v0.11.0 replaced the planned
desktop-polish theme with blocked-region first run and said desktop polish
moves to v0.12.0 and language to v0.13.0, but the roadmap file was never
amended. Persian now ships first as v0.12.0; desktop polish moves to v0.13.0
and the roadmap is amended in this release.

## Success criteria / definition of done

1. `language` is a validated engine setting with values `system`, `en` and
   `fa`, default `system`, persisted in `config.toml`/`state.json`, exposed
   additively in `SettingsView`, and changeable through `settings_set`.
2. The Windows GUI and Android phone/TV render every user-facing string in
   Persian when Persian is selected, and in English otherwise. TUI and CLI
   stay English.
3. `system` resolves to Persian only when the OS UI language is Persian;
   every other system language resolves to English.
4. The full UI is right-to-left in Persian: navigation, text alignment,
   directional icons, charts/progress and focus order mirror; flags, brand
   marks and the power icon do not.
5. Persian uses Vazirmatn 33.003 (four static weights), Persian digits and
   Jalali dates. IP addresses, ports, versions and email addresses stay
   Latin.
6. Errors show a Persian summary and action; raw engine details, logs and
   diagnostic facts stay English in their details area. Country, city,
   server and account names stay as supplied.
7. Language is selectable inline on the first setup step and as the first
   row of Settings → Kumiho app (`System`, `English`, `فارسی`), applies
   immediately, and never resets setup progress or disconnects the tunnel.
8. String-coverage tests prove the English and Persian catalogs have the same
   keys, no empty translations and matching format arguments. An Android
   emulator suite proves RTL layout direction and mirrored navigation. A
   Persian GUI visual capture is reviewed before the tag.
9. `README.fa.md` is a full RTL Persian translation of the README with Persian
   screenshots, linked from the English README. `docs/translations/fa.md`
   records the glossary and conventions.
10. The Go gate, race tests, Android JVM/lint/assemble and connected suites
    are green; control protocol v1 stays byte-compatible; the v0.12.0 draft
    release carries versioned primary assets and stable aliases.

## Scope

### In scope

- Engine: `language` config key, state override, validation, `SettingsView`
  field and `settings_set` support.
- Persian and English catalogs for the Windows GUI web UI, the Windows tray,
  and Android phone/TV, including notifications, Quick Settings tile, home
  screen widgets and the Google TV channel.
- Full RTL layout, Vazirmatn assets, Persian digits, Jalali dates, bidi
  isolation for mixed Persian/Latin values.
- First-run language selection on the GUI welcome/consent step and the
  Android phone/TV consent step; Language row in Settings.
- GUI language cache in `gui.toml`; Android language mirror in DataStore for
  pre-engine and system surfaces.
- Tests: catalog parity, settings validation, controller message codes,
  Android locale/RTL, GUI RTL visual review.
- Docs: roadmap amendment, `README.fa.md`, `docs/translations/fa.md`,
  English docs updates, CHANGELOG, README, screenshots.
- Release: v0.12.0 draft release with versioned primary assets and stable
  aliases.

### Non-goals (explicitly out)

- TUI, CLI or `kumiho` daemon log localization.
- Any language other than English and Persian.
- Translating English documentation beyond `README.fa.md`.
- Desktop polish, auto-update, proxy automation or network rules; that work
  moves to v0.13.0.
- New features, DNS or routing work, macOS support, or a protocol break.
- A new Go or Android dependency. Vazirmatn is a vendored font asset only.
- Runtime translation updates or a translation service.

## Architecture

### Engine setting

`internal/settings.Config` gains `Language string` (`toml:"language"`), default
`system`, validated against `system|en|fa`. `internal/settings.Store` gains a
`Language` override pointer, includes it in `SetOverride`, `ClearOverride` and
`OverriddenKeys`, and treats an unknown stored value as `system` on read.
`internal/api.SettingsView` gains `Language` with `json:"language"`.
`Controller.ApplySetting` accepts `language` through the existing generic path;
it persists the override and notifies clients but has no live engine consumer.
`internal/gui/controller.go` copies the field into its settings projection and
exposes the resolved effective language (`en` or `fa`).

### Windows GUI

- **Catalogs.** `internal/gui/web/static/i18n/en.json` and `fa.json` hold every
  user-facing web string under stable `screen.element` / `common.*` keys. A
  small `i18n.js` loads the selected catalog before the shell mounts, exposes
  `t(key, params)`, sets `document.documentElement.lang` and `dir`, and keeps
  the body hidden until ready. Missing keys fall back to English; coverage
  tests fail the build.
- **Controller projection.** `Notice` gains `Code` and `Params`; `StatusView`
  gains raw values (state code, connected-since epoch, byte rates/totals,
  token/pass expiry epochs, quota reset epoch) alongside the existing English
  fallback strings. Service state, relay tests, update checks and login errors
  gain stable codes. JS formats durations, byte rates, Persian digits and
  Jalali dates with `Intl`.
- **Tray.** A small Go catalog in `internal/gui` owns the tray tooltip prefix,
  Connect/Disconnect, Show, Diagnostics, Quit, the location fallback and the
  first-close hint. The tray reads the controller's effective language and
  refreshes the tooltip/menu; "Kumiho" stays untranslated.
- **Prefs and startup.** `gui.toml` gains `language` as the last effective
  value. The host renders with that cache, then reconciles with the engine
  setting when state arrives. A language change in Settings updates the cache,
  the controller projection and the live UI without a page reload.
- **Layout.** `dir="rtl"` on the document, logical CSS properties, rail on the
  right, mirrored directional icons, mirrored progress/quota geometry, and
  Persian-specific line height. Flags, the brand, and the power icon do not
  mirror. Vazirmatn is loaded with `@font-face` only for `fa`.
- **Setup and Settings.** The onboarding welcome/consent step gets an inline
  three-choice control (System / English / فارسی). Settings → Kumiho app gets
  the same row above Theme. Both write `settings_set language` immediately and
  keep the current route/step.

### Android

- **Catalog.** `res/values-fa/strings.xml` mirrors `values/strings.xml` key for
  key. Hardcoded Compose strings move to resources; plurals and format
  arguments are checked by a JVM parity test. Existing English resource names
  stay unchanged.
- **Locale resolution.** A small `LanguageRepository` combines the engine
  `language` value with a DataStore mirror, resolves `system` from the OS
  locale, and exposes `en|fa`. A localized `Context`/`Configuration` is
  provided at the Compose root so `stringResource` switches immediately; a
  localized context is also used for notification channels, notifications,
  the Quick Settings tile, widgets and the Google TV channel. No AppCompat or
  new dependency.
- **RTL.** `android:supportsRtl` is already on. Compose mirrors navigation and
  text automatically; custom geometry, offsets, arrows and progress controls
  are audited and use `AutoMirrored` icons or direction-aware layout. Flags,
  the brand and the power icon do not mirror.
- **Typography and formats.** Vazirmatn TTF assets are used only when the
  effective language is Persian; English keeps the system font. Persian line
  height is increased. `NumberFormat`/date formatting with `fa-IR` provides
  Persian digits and Jalali dates; technical identifiers stay Latin.
- **Setup and Settings.** The consent step gets the inline language control;
  Settings → Kumiho app gets the Language row. Changing it writes the engine
  setting and the mirror, recomposes immediately, updates system surfaces and
  keeps the setup step.
- **Errors.** Known engine error codes map to Persian summaries; the raw
  message stays available as English detail/log text. Unknown errors show a
  generic Persian summary plus the English detail.

### Shared Persian content

`docs/translations/fa.md` records the glossary (VPN, tunnel, proxy, relay,
kill switch, account, sign-in, quota, split tunneling, blocked region), the
formal register, Persian punctuation, digit/date rules and bidi handling. The
English catalogs remain the source of truth; Persian catalogs must cover every
key.

### Tests and gates

- Go: settings validation/override tests, IPC compatibility tests for the
  additive field, GUI catalog parity and key-use tests, controller code/raw
  projection tests, tray catalog tests, prefs cache tests, static RTL checks.
- Android: JVM catalog parity/format-argument tests, locale resolution and
  formatting tests, settings-mapper tests, and connected emulator tests that
  assert RTL layout direction and mirrored rail/navigation. Existing Android
  JVM, lint, assemble and connected suites stay green.
- GUI: `scripts/visual/capture.mjs` gains a Persian mode used to capture the
  committed Persian screenshots; the review checklist covers every screen,
  the tray and setup. No Playwright CI job.
- Release gate: Go gate, race tests, Windows/Android cross-builds, Android
  suites, Persian visual review, then the draft release.

## Risks + rollback

| Risk | Mitigation / rollback |
| --- | --- |
| Translation coverage or quality slips | Catalog parity tests fail the build; the user reviews the running Persian UI before tagging; missing strings fall back to English |
| RTL regressions hide in custom layout code | Full CSS/Compose audit, emulator RTL suite, Persian visual capture, manual checklist |
| Android pre-13 locale switching behaves differently | Localized context at the Compose root plus localized contexts for native surfaces; API 36 is the CI target, API 26 is the minimum contract |
| The controller refactor changes existing GUI behavior | Keep English fields/messages as fallbacks; add codes/raw values additively; existing tests stay green |
| Vazirmatn licensing or size | Vendor v33.003 with OFL-1.1 text and checksums; four static weights only; bundled locally |
| Full README translation drifts | Link it from the English README and update it in the release checklist |
| Release aliases confuse download links | Versioned files are primary in the release notes; stable aliases keep `/latest` links; `SHA256SUMS` covers both |
| Scope grows beyond language | Desktop polish, other languages and docs translation are explicit non-goals; the roadmap moves desktop polish to v0.13.0 |

Rollback: set `language = en` or `system`; no data migration exists. Code
rollback is safe because the setting is additive and older clients ignore it.

## Dependencies / ordering

- Baseline: shipped v0.11.1.
- Vazirmatn v33.003 assets and OFL-1.1 license must be vendored before the
  Android/GUI font work.
- Engine setting first, then client projections, then Persian catalogs, then
  RTL/typography, then screenshots/docs/release.
- User translation review happens after the Persian UI is built and before
  the tag.
- No release is tagged, pushed or published without an explicit request.
