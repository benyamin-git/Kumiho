# v0.10.0 Android polish — Design Spec

**Status:** Approved
**Date:** 2026-11-05

> Roadmap: [2026-10-23-v0.6.0-roadmap-design.md](2026-10-23-v0.6.0-roadmap-design.md),
> v0.10.0 row. This spec adds two approved exceptions to that roadmap's
> non-goals; the roadmap is amended in the same docs change.

## Objective / why

Close the remaining Android gaps on top of the shipped v0.9.3 baseline: two
home-screen widgets that share the Quick Settings tile's truth, AAAA
suppression in the in-tunnel resolver, a 25 s keepalive default, and the
GlobalSign Root R46 anchor for edge dials. The release touches no routing, no
DNS privacy, no desktop UI and no new settings keys.

## Success criteria / definition of done

1. On a phone, the launcher offers **Kumiho toggle** (1×1) and **Kumiho
   status** (2×1); both render from the same coordinator snapshot the tile
   reads, and both drive the same connect/disconnect path.
2. The 1×1 toggle shows distinct on/off glyphs plus a state content
   description; the 2×1 shows the state word, the connected location and the
   quota line exactly as the copy table below specifies.
3. A widget tap with missing VPN consent opens the transparent
   `WidgetConnectActivity`, and a granted consent completes the connect without
   leaving the launcher.
4. The in-tunnel DNS server answers every AAAA question with an empty
   NOERROR/NODATA reply, strips AAAA records from ANY replies, and never caches
   a suppressed answer. This holds on Android, Linux and Windows.
5. Fresh configs on every platform default `keepalive_profile` to `slow`;
   explicitly stored values always win, and a test proves desktop and Android
   share the default.
6. `upstream.EdgeRootCAs()` contains both GlobalSign Root E46 and GlobalSign
   Root R46 anchors, each covered by a pinned SHA-256 fingerprint test.
7. `kumiho doctor` describes the new AAAA behavior instead of saying it does
   not strip AAAA.
8. Documentation no longer claims there is no widget and that DNS may return
   AAAA; CHANGELOG and the Gradle default version read v0.10.0.
9. Gates: `make lint && make test && go test -race -count=1 ./... && make
   build`, Windows/Android cross-builds, `make android-test`, and the emulator
   suite. No tag, push or publish without an explicit request.

## Scope

### In scope

- 1×1 connect-toggle and 2×1 status widget, phone only, immutable
  PendingIntents, shared with the tile's process-local status.
- AAAA suppression in the in-tunnel resolver, all platforms.
- `keepalive_profile = "slow"` as the engine default on all platforms.
- GlobalSign Root R46 vendored beside E46 and merged into the edge trust pool.
- The doctor detail text for IPv6, the four documentation surfaces, the
  roadmap exception note, CHANGELOG and the version bump.

### Non-goals (explicitly out)

- TV or launcher long-press widgets, widget configuration activities.
- Any desktop UI, settings or control-protocol change; the only desktop
  behavior change is the shared DNS answer and the shared keepalive default.
- New settings keys, migrations, or changes to `internal/ipc` envelopes.
- Smart routing, DNS privacy, blocklists, FakeDNS, IPv6 connectivity.
- Language/RTL work (v0.12.0), auto-update or installer work (v0.11.0).
- Screenshot regeneration, tagging, pushing, publishing.

## Architecture

### Widgets

Components, all in `android/app/src/main/java/dev/benyamin/kumiho/widget/`:

- `KumihoToggleWidgetProvider` — 1×1 receiver, `RemoteViews` for
  `widget_toggle_info.xml`.
- `KumihoStatusWidgetProvider` — 2×1 receiver, `RemoteViews` for
  `widget_status_info.xml`.
- `WidgetState` — pure reducer: `reduce(snapshot: TileSnapshot?, size:
  WidgetSize): WidgetPresentation`. No Android types, JVM-tested.
- `WidgetRefresh` — helper that renders both providers from the current cache,
  asks `AppWidgetManager` to update present ids, and is a no-op when none
  exist.
- `WidgetConnectActivity` — transparent, `noHistory`, launched by the toggle
  when `VpnService.prepare` is non-null.

State flow:

```
KumihoVpnService → VpnServiceCoordinator.state
  → VpnStatusCache.update (TileSnapshot + quota)
    → TileState.reduce            (tile, unchanged behavior)
    → WidgetState.reduce          (1×1 / 2×1)
      → WidgetRefresh → RemoteViews
ThemeRepository.state (Ready palette)  → WidgetRefresh
```

`TileSnapshot` gains the engine's `Quota?`; the coordinator's existing
collector fill it. The tile's refresh guard compares the presentation without
quota, so a quota poll never wakes the system tile.

Presentation, per state:

| Condition | 1×1 glyph (content description) | 2×1 line 1 | 2×1 line 2 |
| --- | --- | --- | --- |
| No snapshot | off, "Service unavailable" | Service unavailable | — |
| Off, consent granted | off, "Not connected" | Not connected | — |
| Off, consent missing | off, "VPN permission needed" | VPN permission needed | — |
| Connecting / in flight | on, "Connecting" | Connecting… | — |
| Reconnecting | on, "Reconnecting" | Reconnecting… | `CC · NN% left` |
| Waiting | on, "Waiting for network" | Waiting for network | `CC · NN% left` |
| Connected | on, "Connected · CC" | Connected | `CC · NN% left` |
| Proxy only | on, "Proxy only" | Proxy only | `NN% left` |
| Not signed in | off, "Sign in required" | Sign in required | — |
| Error | off, "Connection error" | Connection error | `CC · NN% left` if reported |
| Binding unavailable | off, "Service unavailable" | Service unavailable | — |

Line 2 is at most two segments joined by ` · `: the location (country code,
omitted when `rec` or blank) and the quota. The quota is `NN% left` only when
`limit` and `remaining` are both reported, otherwise `Quota unknown`. A row
whose line 2 has neither segment hides the line.

Taps:

- 1×1: whole area toggles — disconnect when active, otherwise connect the
  saved selection; missing consent launches `WidgetConnectActivity`.
- 2×1: icon area toggles; the text area opens `MainActivity`.
- Both use explicit immutable PendingIntents; the receivers and activity are
  not exported.

Consent: `WidgetConnectActivity` calls `VpnService.prepare`, shows the system
dialog, and on `RESULT_OK` calls `VpnServiceCoordinator.connect(ConnectRequest())`
and finishes; any other result finishes silently, leaving the widget honest.

Presentation: the palette comes from `ThemeRepository.state`; widgets do not
render until it is `Ready`. The background uses the theme's surface-container
role, text uses on-surface, the active glyph uses primary, and the off glyph
uses on-surface-variant/outline. Colors are applied through RemoteViews color
methods from `KumihoColors`; no raw hex in layouts. Corner clipping is the
launcher's; there are no shadows, gradients or decoration (design bans 1, 2,
7, 9 and the accessibility floor).

Strings: `tile_subtitle_*` for state words, `account_row_quota_left` and
`account_row_quota_unknown` for the quota line, plus new
`widget_toggle_label`, `widget_status_label`, and content-description strings.

### DNS

`internal/dns.Server.HandleQuery` gains an early branch:

1. Exactly one question, as today.
2. If `q.Qtype == dns.TypeAAAA`: return a reply with `RcodeSuccess`, the
   question echoed, no answer records, and no cache write. Log at debug.
3. Otherwise resolve as today; for `dns.TypeANY`, remove every `AAAA` record
   from `Answer` before the server cache write and before returning.
4. Truncation/EDNS handling stays exactly as today.

The path is shared, so Android, Linux and Windows all answer the same way. The
endpoint `Resolver` is unchanged; suppression is a server policy applied
before and after resolution. `kumiho doctor`'s IPv6 detail becomes "IPv6
enabled; the tunnel answers AAAA empty and blackholes IPv6".

### Settings

`settings.DefaultConfig()` returns `keepalive_profile = "slow"`. `Open`,
`EffectiveConfig`, validation, the `standard` option and the TUI/GUI/Android
editors are unchanged, so a stored `standard` still wins. No migration: configs
without the key inherit the new default on the next read.

### Roots

`internal/upstream/roots/globalsign-root-r46.pem` holds the Mozilla-bundle
GlobalSign Root R46 (`CN = GlobalSign Root R46`, SHA-256
`4F:A3:12:6D:8D:3A:11:D1:C4:85:5A:4F:80:7C:BA:D6:CF:91:9D:3A:5A:88:B0:3B:EA:2C:63:72:D9:3C:40:C9`).
`EdgeRootCAs()` appends both embedded PEMs into the system pool; the comment
and tests cover both anchors.

## Risks + rollback

- **Stale widget art.** With push-only refresh, a widget can show the last
  render after the app process dies. Accepted; the launcher's next update or
  app start corrects it.
- **RemoteViews color limits.** API 26-30 hosts may not clip corners to the
  design radius. The background color still follows the theme; no layout
  depends on the radius.
- **AAAA suppression is visible on desktop.** Apps that query AAAA now get
  NODATA instead of records they could not reach; IPv6 was already blackholed.
  Rollback: remove the early branch.
- **Default change affects fresh desktop installs.** Stored values win, and
  rollback is restoring `"standard"` in `DefaultConfig`.
- **Root pinning.** A corrupted PEM fails the fingerprint test; R46 is a
  published Mozilla-bundle asset.
- **Tile cache change.** Adding quota to the shared snapshot could wake the
  tile; the plan pins a comparison that ignores it.

## Dependencies / ordering

- The Go items (DNS, settings default, R46) are independent of the widgets and
  can land first behind the Go gate.
- Widgets depend only on the shipped v0.9.3 Android client; `VpnStatusCache`
  and `ThemeRepository` already exist.
- Docs and the release commit come last; the roadmap amendment rides with the
  docs change.
- No release depends on v0.11.0 or v0.12.0.
