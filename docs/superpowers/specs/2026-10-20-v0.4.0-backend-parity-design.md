# Kumiho v0.4.0 Backend Parity — Design Spec

**Status:** Approved
**Date:** 2026-10-20

## Objective / why

Bring Kumiho's backend up to the behavior FoxyVPN shipped after the release we
ported (v1.0.5–v1.0.7, Oct 13–17 2026), and close the reliability and
anti-censorship gaps found while comparing the two. The release has four
user-visible outcomes:

1. **DNS that can actually work.** The in-tunnel resolver currently falls back
   to plaintext DNS over TCP:53 after a DoH failure. The live Fastly edge
   refuses CONNECT to port 53 (verified 2026-10-20: 53/853/444 rejected, 80/443
   accepted), so every DoH failure costs an 8 s stall and still ends in
   SERVFAIL. v0.4.0 replaces that dead path with a serial DoH failover chain.
2. **Resilience around the control plane.** A persistent server-list cache, a
   five-attempt Guardian challenge retry, and a sign-out that leaves no
   account/session data behind.
3. **Anti-censorship controls.** An opt-in TLS ClientHello fragmentation mode
   for the edge and control-plane handshakes, and a real Fastly anti-bot
   challenge solver that replaces today's "not implemented" failure.
4. **The advertised-but-missing proxy surfaces.** `upstream_proxy` becomes
   functional, a local HTTP proxy joins SOCKS5, and SOCKS5 UDP ASSOCIATE
   finally serves DNS.

The same release also exposes the slow-network keepalive profile, keeps the
8500 TUN MTU (with the divergence documented), and updates every canonical
document so the repo stops claiming things it does not do.

Reference documents (canonical, not duplicated here):

- `PLAN.md` — living architecture and protocol design.
- `README.md`, `docs/usage.md`, `docs/manual.md`, `docs/troubleshooting.md` —
  user-facing behavior and limitations.
- `docs/cli-tui-abilities.md`, `docs/gui-feature-inventory.md` — the complete
  client surface; both are behavioral authority for the clients.
- `AGENTS.md` — architecture map, gate, vendor and commit rules.
- Upstream reference: `vauth/FoxyVPN` tags v1.0.5–v1.0.7 (MIT) and the
  unlicensed `UjuiUjuMandan/firefox-vpn-client` (behavior reference only).

## Success criteria / definition of done

1. **Strict in-tunnel DNS.** No code path opens a DNS connection to port 53
   inside the tunnel. A failed DoH endpoint is followed by the next endpoint in
   the chain, and a failed endpoint is suppressed for 30 minutes. Verified by
   unit tests for the chain and suppression, plus an integration-tag test that
   forces the first endpoint to fail.
2. **Server-list cache.** `<state dir>/serverlist.json` is written atomically
   (0600) after a successful fetch and read when a fetch fails, including the
   first fetch after daemon start. A corrupt cache is ignored with a warning
   and never prevents a connect attempt that could otherwise proceed.
3. **Challenge solving.** With `solve_challenges=on` (default), a 406 from FxA
   or Guardian triggers the solver against the challenged origin (falling back
   to the related apex), installs cookies into the shared control-plane jar,
   and retries up to five times with 250–750 ms jitter. A captcha or an
   exhausted budget produces a clear, actionable error; no silent hang.
4. **TLS fragmentation.** `tls_split` accepts `off`, `first-byte` and `sni`,
   defaults to `off`, and applies to the edge H2 handshake and every
   control-plane HTTPS request (FxA, Guardian, Remote Settings, solver), but
   not to DoH/bootstrap. A unit test proves the ClientHello is segmented at the
   intended offset and the handshake still succeeds.
5. **Upstream proxy.** `upstream_proxy` honors `socks5://`, `socks5h://` and
   `http://` URLs with optional credentials, applies to the edge dial only,
   sends the edge hostname unresolved (no local DNS leak), and composes with
   `edge_address` pinning. Verified against in-test SOCKS5 and HTTP proxies,
   including auth and a remote-resolution assertion.
6. **Local HTTP proxy.** When `http_proxy=on`, a loopback listener on
   `http_proxy_port` (default 8080) accepts CONNECT and absolute-form plain
   HTTP through the same tunnel, refuses loopback/private/link-local/CGNAT
   targets exactly like SOCKS, and stops with the SOCKS listener. Covered by
   handshake/relay/refusal tests.
7. **DNS-only UDP ASSOCIATE.** SOCKS5 UDP ASSOCIATE succeeds for target port
   53 (or 0), relays DNS payloads through the DoH chain, drops foreign and
   non-DNS datagrams, enforces 32 in-flight queries and 64 KiB, answers
   SERVFAIL when the provider is `off`, and works in full-tunnel and
   proxy-only modes.
8. **Keepalive profile.** `keepalive_profile=standard|slow` selects a 10 s or
   25 s ping timeout (idle stays 15 s) on the next connect; the default
   remains `standard`.
9. **Settings surface complete.** All five new keys exist in `config.toml`,
   `state.json` overrides, `SettingsView`, the TUI (with a scrolling list) and
   the GUI “Background service” section, with defaults, validation and
   reset-to-default behavior.
10. **Clean sign-out.** Logout/session clear wipes quota, exit IP/country,
    rates and totals; the anonymous status view exposes none of them.
11. **Documentation is true.** CHANGELOG `[0.4.0]`, README status and known
    limitations, PLAN.md, usage/manual/troubleshooting, both ability
    inventories, `install.sh` sample config, `NOTICE` (solver attribution) and
    the AGENTS architecture map are updated. Dated specs and plans are left
    untouched.
12. **Gate green.** Every commit passes
    `make lint && make test && go test -race -count=1 ./... && make build` and
    the Windows/Android cross-builds from `AGENTS.md`; no new dependency is
    added and `vendor/` is unchanged.
13. **GUI proof.** The new rows render in the dev harness under the mock daemon
    in Light, Dark and OLED, verified with Playwright captures; the
    accessibility floor and the twelve bans still pass.
14. **Release framing.** README/CHANGELOG say v0.4.0 and the release notes
    describe the parity work; no tag is created and nothing is pushed.

## Scope

### In scope

- Workstream A: strict DoH with serial failover and 30-minute suppression;
  removal of the in-tunnel TCP:53 path; persistent server-list cache; Guardian
  5× challenge retry; sign-out wipe; the 80/443 documentation correction.
- Workstream B: optional TLS ClientHello fragmentation (first-byte and SNI)
  for edge and control-plane handshakes.
- Workstream C: Fastly anti-bot solver ported from FoxyVPN (MIT), shared
  control-plane cookie jar, FxA/Guardian wiring, `solve_challenges` setting.
- Workstream D: functional `upstream_proxy` (edge only, remote resolution,
  SOCKS5/SOCKS5h/HTTP), DNS-only UDP ASSOCIATE.
- Workstream E: local HTTP proxy (CONNECT + absolute-form HTTP) alongside
  SOCKS5.
- Workstream F: keepalive profile setting; MTU default retained and documented.
- Settings plumbing, TUI scrolling, GUI rows, both inventories.
- Tests (unit + integration tag), Playwright captures, all docs, CHANGELOG
  v0.4.0, NOTICE attribution, AGENTS architecture map, `install.sh` sample.

### Non-goals (explicitly out)

- **No Android/mobile parity work:** GlobalSign root bundling, 1400 MTU
  default, 25 s default keepalive, foreground-service types, widgets,
  Android UDP relay, pending-session persistence, zero-width input stripping.
- **No transport change:** still HTTP/2 CONNECT to the Fastly edge; no MASQUE,
  HTTP/3, or WireGuard.
- **No IPC v2:** no new commands, no envelope change, no change to existing
  `SettingsView` fields. New fields are additive and optional.
- **No new dependencies**, including `utls`; fragmentation uses stdlib
  `net.Conn` wrapping.
- **No `internal/platform` seam changes**; the engine wires everything.
- **No GUI redesign:** new rows follow the existing Settings patterns and the
  approved house style.
- **No captcha solving, no interactive challenge UI, no browser automation.**
- **No tag, push, release upload, or package publication.**
- **No non-DNS UDP**; QUIC/VoIP/games stay blocked.
- **No SOCKS bind-address change** (loopback only) and no HTTP proxy auth.
- **No persistent DoH endpoint suppression** (in-memory per daemon).
- **No plaintext DNS fallback inside the tunnel.**
- **No MTU default change.**

## Architecture

### Settings and wire surface

Five new keys flow through the existing settings stack:

- `settings.Config`: `TLSSplit` (string), `HTTPProxy` (bool), `HTTPProxyPort`
  (int), `SolveChallenges` (bool), `KeepaliveProfile` (string), plus defaults
  and validation (`Validate`: enum checks, port range).
- `settings.State`: pointer overrides for each key, wired through
  `SetOverride`, `ClearOverride`, `OverriddenKeys` and `effectiveConfigLocked`.
  `state.json` remains 0600 and additive; older binaries ignore unknown keys.
- `api.SettingsView`: five new optional JSON fields (`tls_split`, `http_proxy`,
  `http_proxy_port`, `solve_challenges`, `keepalive_profile`). No existing field
  changes; the envelope and command set are untouched.
- TUI: the fixed row list becomes a viewport (window over rows with scroll
  cues), preserving the existing editors and reset semantics; all existing and
  new rows remain reachable in short terminals.
- GUI: append the five rows to `SERVICE_ROWS` in the canonical order, using the
  existing toggle/cycle/number controls; no new component type or visual
  language.

Connection-scoped values are read through `EffectiveConfig()` at connect time.
`solve_challenges` is consulted per request by the engine's solver callback.

### TLS fragmentation (`internal/tlsplit`)

A `net.Conn` wrapper, installed at dial time, that inspects the first write:

- If the buffer does not start with a TLS ClientHello (`0x16 0x03 … 0x01`), the
  write passes through untouched.
- `first-byte`: write byte 0, then the remainder, flushing between.
- `sni`: locate the SNI hostname inside the ClientHello, write
  `[0, start)`, the first hostname byte, then the remainder, flushing between.
- All other `net.Conn` methods delegate; deadlines and close semantics are
  preserved.

Two dial boundaries install it, both reading the mode from the effective config
at dial time: the control-plane `http.Transport.DialContext` (FxA, Guardian,
Remote Settings, solver) and the edge dial (after any upstream proxy hop, before
TLS). DoH/bootstrap dials are explicitly excluded.

### Challenge solving (`internal/fastly`)

- `Solver` takes the URL that returned 406. It fetches the challenge page from
  the challenged origin; if that origin serves no challenge, it retries the
  related apex (for `api.accounts.firefox.com`, `accounts.firefox.com`).
- It parses `/_fs-ch-*` and the last `init([…], "token", "prefix")`, then
  answers each challenge type: `pow` (SHA-256 over `base` + a two-character
  alphabet suffix), `pat` (`POST …/pat?token=…`), and `clientmetrics` (the
  static non-bot payload). It posts answers to `…/fst-post-back` for up to
  three rounds, installs the resulting cookies into the shared jar, and
  verifies the challenge is gone before returning.
- Unsupported types (captcha) fail with a specific error. Total budget 60 s;
  rounds are separated by 250–750 ms jitter; every attempt is logged at warn.
- The engine builds one `cookiejar.Jar` and attaches it to the FxA, Guardian
  and Remote Settings clients. The solver uses an isolated jar while working
  and copies cookies into the shared jar for the challenged URL. FxA's
  `ChallengeSolver` interface and Guardian's `OnChallenge` callback gain the
  challenged URL so both can drive the same solver.
- `solve_challenges=off` restores today's immediate, clearly worded failure.

### DNS (`internal/dns`)

- The resolver builds a serial endpoint chain: the configured provider first
  (or the custom `dns_upstream` IP as `https://<ip>/dns-query`), then
  Cloudflare (`1.1.1.1`), then Quad9 (`9.9.9.9`), de-duplicated.
- A failed endpoint is suppressed for 30 minutes in memory; the next endpoint
  is tried within the same query budget. Successful answers keep today's TTL
  cache, truncation handling and question/opcode validation.
- The plaintext `tcpQuery` path is removed from the in-tunnel resolver. The
  bootstrap resolver outside the tunnel keeps its existing DoH-by-IP chain and
  TCP:53 fallback, because it never crosses the edge.

### SOCKS5 UDP ASSOCIATE (`internal/socks`)

- UDP ASSOCIATE is accepted for target port 53 or 0, on a loopback UDP socket
  returned in the reply; one association per client.
- The server validates the SOCKS5 UDP request header, extracts the DNS payload,
  and resolves it through a `DNSResolver` interface backed by the same DoH
  chain as the in-tunnel resolver.
- Limits: 32 in-flight queries, 64 KiB messages, foreign-source datagrams
  dropped and counted; non-port-53 datagrams are dropped with a debug log.
  Provider `off` answers SERVFAIL; malformed queries are dropped.
- The relay does not depend on the TUN or the local 10.8.0.2 listener, so it
  works in proxy-only mode too.

### HTTP proxy (`internal/httpproxy`)

- A loopback listener sharing the SOCKS lifecycle (started with it, stopped
  with it), gated by `http_proxy`, on `http_proxy_port`.
- CONNECT: reply `200 Connection Established`, then relay both directions with
  the same 32 KiB buffers and 2 min half-close drain as SOCKS.
- Absolute-form HTTP: rewrite the request-target to origin-form, strip
  `Proxy-Connection` and hop-by-hop headers, open one tunneled stream to
  `host:80`, and relay the response; connections are not reused across
  requests.
- Target policy mirrors SOCKS: loopback/private/link-local/multicast/CGNAT/ULA
  destinations are refused; 512 concurrent clients; per-connection timeouts
  match the SOCKS server. No authentication (loopback only).

### Upstream proxy (`internal/engine`)

- A dial wrapper around the existing bypass dialer, used only for the edge
  connection. `socks5://` and `socks5h://` use a SOCKS5 CONNECT with the
  hostname (remote resolution); `http://` uses an HTTP CONNECT with the
  hostname. URL credentials become SOCKS5 username/password or
  `Proxy-Authorization: Basic`.
- If `edge_address` pins an IP, the proxy is asked for that IP while TLS SNI
  and the H2 `:authority` keep the edge hostname; otherwise the edge hostname
  is sent unresolved, so local bootstrap DNS is not consulted for the dial.
- The control plane and DoH remain on the marked direct dialer. Credentials
  live in the existing 0600 `state.json` URL; no new secret store.
- Tests use in-process SOCKS5 and HTTP proxy servers, including auth rejection
  and an assertion that no local resolution occurred.

### Server-list cache (`internal/serverlist` + engine)

- `<state dir>/serverlist.json` holds the raw Remote Settings payload,
  written atomically with 0600 after every successful fetch.
- `Controller.Locations` keeps its in-memory TTL cache; on a failed fetch it
  loads the disk cache (if present) and logs a warning. Corrupt or empty files
  are ignored and deleted, never fatal.
- The cache is disposable: no migration, no versioning.

### Session cleanup

`clearSession` already clears tokens and stops the tunnel; v0.4.0 also drops
`quota`, `exitIP`/`exitCountry`, `ratesUp`/`ratesDown` and `totalsUp`/
`totalsDown`, so an unauthenticated snapshot carries no account or usage data.

### Keepalive

`upstream.Options.KeepaliveTimeout` is chosen from the profile at connect time
(`standard` 10 s, `slow` 25 s). Idle (15 s) and check interval (3 s) are
unchanged. No other constant changes, and the MTU default stays 8500.

### Observability

New log tags: `fastly` (solver attempts and outcome at warn), `tlsplit`
(segmentation at debug), `httpproxy` (listener, refusals, drops), `dns`
(endpoint failover/suppression), `serverlist` (cache read/write failures).
Secrets (proxy credentials, challenge tokens/cookies) are never logged;
`redact_targets` continues to apply to hostnames.

## Risks + rollback

| Risk | Mitigation | Rollback |
| --- | --- | --- |
| Fastly changes its challenge page or adds a captcha | Caps, jitter, fixtures, explicit errors; no browser automation | `solve_challenges=off` restores the previous clear failure |
| TLS fragmentation breaks a middlebox or is unnecessary | Off by default, per-connection, stdlib-only wrapper | `tls_split=off` |
| Upstream proxy leaks DNS or mishandles auth | Hostname sent unresolved; in-test proxies assert resolution and auth | Clear `upstream_proxy` |
| Local HTTP proxy is reachable beyond loopback | Loopback bind, local-target refusal, off by default | `http_proxy=off` |
| UDP ASSOCIATE is abused as an open relay | DNS-only, port 53/0, loopback, foreign-source drop, in-flight cap | Refuse UDP ASSOCIATE again |
| DoH failover adds latency when an endpoint is down | Serial only on failure, 30 min suppression, per-query budget | Revert to configured-provider-only behavior |
| Stale server list from the cache points at dead edges | Fallback only, refreshed on every success, existing edge alternates | Delete `serverlist.json` |
| Additive `SettingsView` fields surprise an old client | Optional fields, unknown-field tolerance, no existing field changes | Old clients keep working; no rollback needed |
| New state keys confuse an older daemon | Go ignores unknown JSON keys; state remains 0600 | Reinstall the older binary |
| Solver port lacks attribution | `NOTICE` + source comments cite FoxyVPN (MIT) | — |

## Dependencies / ordering

- **External:** Mozilla's FxA, Guardian and Remote Settings endpoints; no new
  libraries, network access for builds, or platform capabilities.
- **Internal ordering:** M0 (settings scaffolding, TUI viewport, GUI rows)
  precedes every feature. Workstream A's DoH chain is reused by D's UDP relay.
  B lands before C so the solver's requests inherit fragmentation, and before D
  so the split wrapper composes with the proxy dial. E reuses the SOCKS relay
  and target policy. F is independent. Documentation and the release checklist
  close the arc.
- **No migration:** new settings default, new state keys are additive, the
  cache is disposable, and the protocol is backward-compatible.
